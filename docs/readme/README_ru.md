## Установка с помощью coding-агента

Вставьте это в Claude Code, Codex или любой coding-агент, который может выполнять команды на машине, где вы хотите использовать Studiolo:

```text
Установи Studiolo из https://github.com/a554b554/studiolo: клонируй репозиторий, убедись, что доступен Node.js 22.14+ и что установлены CLI `claude` и/или `codex`, запусти `node src/server.mjs` из корня репозитория, проверь, что http://127.0.0.1:4310 отвечает, затем скажи мне открыть Settings → Hosts & accounts, чтобы войти в мои аккаунты. Сам ни в какие аккаунты не входи.
```

Или вручную:

```sh
git clone https://github.com/a554b554/studiolo studiolo && cd studiolo
node src/server.mjs        # http://127.0.0.1:4310
```

У Studiolo нет npm-зависимостей; `npm install` не нужен. Тесты: `node --test test/*.test.mjs`.

## Что это такое

Studiolo — самохостируемый веб-верстак, который управляет CLI **Claude Code** и **Codex**, уже установленными на ваших компьютерах. Это не очередной чат-интерфейс поверх API-ключа:

- **Ваши подписки, ваши CLI.** Каждый запрос проходит через настоящий процесс `claude` или `codex` — те же инструменты, skills, MCP-серверы, режимы разрешений и поведение агента, что и в терминале. Вход по подписке или API-ключ — выбор для каждого аккаунта отдельно.
- **Аккаунты на каждой машине под управлением Studiolo.** Входите в несколько аккаунтов Claude и Codex на каждом компьютере прямо из браузера. У каждого аккаунта свой изолированный каталог конфигурации CLI; ваши личные `~/.claude` и `~/.codex` не затрагиваются. Квота каждого аккаунта отображается в реальном времени.
- **Одна история проектов на всех машинах.** Проекты лежат в папке, которую вы синхронизируете как угодно (например, через Syncthing). История разговоров — журнал только на добавление, который сливается детерминированно; на каждой машине работает один и тот же сервер и отдаёт одну и ту же историю. Разговор выполняется на машине, выбранной для него; читать и продолжать его можно с любой из них.
- **Опыт терминала в браузере.** Остановите ход клавишей Esc, направляйте работающего агента дополнительным сообщением, наберите `/` для собственных slash-команд CLI — всё отображается на нативные протоколы, а не реализовано заново.
- **Artifacts и комментарии на странице.** Веб-приложения, которые строят агенты, запускаются как Artifacts с постоянными бэкендами и синхронизируемым хранилищем; выделите что-нибудь в превью и отправьте агенту как задачу.

## Быстрый старт

1. **Требования** — Node.js 22.14+ и установленные на машине CLI `claude` и/или `codex` (`claude --version`, `codex --version`).
2. **Запустите** `node src/server.mjs` и откройте <http://127.0.0.1:4310>.
3. **Добавьте аккаунты** — Settings → *Hosts & accounts* → *Add account*. Выберите машину, тип (Claude Code / Codex) и способ входа, затем следуйте показанным шагам (см. ниже).
4. **Создайте проект, начните разговор** — в поле ввода выбираются **машина → аккаунт → модель → effort → режим разрешений**. Первое сообщение закрепляет машину, аккаунт и модель для этого разговора; effort и разрешения можно менять для каждого сообщения.

Переменные окружения: `STUDIO_STATE_DIR` (приватное состояние машины, по умолчанию `~/.studio-local`), `STUDIO_BIND`, `STUDIO_PORT` (4310), `STUDIO_PREVIEW_PORT` (4311), `STUDIO_TOKEN`, `STUDIO_UPLOAD_LIMIT` (в байтах, по умолчанию 100 MB). Один сервер на каталог состояния.

## Аккаунты и вход

Аккаунты принадлежат машине и создаются из браузера. Каждый аккаунт — это каталог в `~/.studio-local/accounts/<id>/`, используемый как `CLAUDE_CONFIG_DIR` или `CODEX_HOME`, поэтому несколько аккаунтов одного CLI сосуществуют, а собственный вход вашего терминала никогда не затрагивается. При создании аккаунта Studiolo заполняет этот каталог из вашего каталога CLI по умолчанию — копирует `settings.json` / `CLAUDE.md` (Codex: `config.toml` / `AGENTS.md`) и создаёт ссылки на `skills`, `plugins` и подобное — так что агенты сохраняют skills и MCP-серверы, которыми вы уже пользуетесь. Учётные данные никогда не копируются.

| Тип | Способ | Что происходит |
| --- | --- | --- |
| Claude Code | **Подписка** | Studiolo запускает `claude auth login`; вы открываете ссылку, входите и вставляете код авторизации обратно на страницу. |
| Claude Code | **API-ключ Anthropic** | Ключ хранится в каталоге аккаунта (mode 0600) и передаётся как `ANTHROPIC_API_KEY`; проверяется через рукопожатие CLI и удаляется, если отклонён. Оплата по факту использования, без окон квоты. |
| Codex | **ChatGPT** | Код устройства через Codex app-server: страница показывает ссылку и одноразовый код; войдите из любого браузера, страница обновится по завершении. |
| Codex | **API-ключ OpenAI** | Хранится самим Codex в `CODEX_HOME` аккаунта. |

После входа Studiolo читает идентичность аккаунта (e-mail, тариф) и список моделей напрямую из CLI — без единого запроса к модели — а для Claude ещё и slash-команды CLI для автодополнения в поле ввода. Аккаунт без собственного имени переименовывается в свой e-mail, поэтому поле ввода, заголовок разговора, каждый ответ и панель использования показывают, кто говорит. Аккаунты можно переименовать, обновить, выйти из них (`claude auth logout` / `codex logout`) или удалить; разговор, аккаунт которого удалён, можно продолжить с другим аккаунтом на той же машине.

Панель использования (внизу слева) следует за машиной, выбранной в поле ввода: подписки Claude показывают 5-часовое окно, Codex — недельное, аккаунты с API-ключом оплачиваются по использованию. Она читает собственные эндпоинты использования CLI (`get_usage`, `account/rateLimits/read`), кэширует на 60 с, никогда не опрашивает и никогда не запускает CLI для аккаунта, из которого выполнен выход.

Всё это работает и для удалённых машин: выберите другой хост в сети в *Hosts & accounts*, и запросы будут переданы на него.

## Чат как в CLI

Каждому разговору принадлежит резидентный нативный процесс — Claude Code через двунаправленный `stream-json`, Codex через `app-server` — поэтому агент ведёт себя точно так же, как в терминале. Веб-элементы управления отображаются на нативные протоколы:

| В терминале | В Studiolo | Как |
| --- | --- | --- |
| Esc для остановки | **■ Stop** или Esc в поле ввода | Управляющий запрос Claude `interrupt` / Codex `turn/interrupt`. Процесс и нативная сессия сохраняются; частичный ответ остаётся; последующие сообщения продолжают ту же сессию. |
| Ввод, пока агент работает | Отправка во время хода = **Steer** | Claude читает сообщение на следующей границе инструмента; Codex — `turn/steer`. Показывается как *You · steer*; ответ продолжается в новом сегменте. **Queue** вместо этого отправляет после хода. |
| `/compact`, `/context`, пользовательские команды, skills | Наберите `/` для списка команд | Команды Claude передаются дословно (список приходит от самого CLI). У Codex нет текстовых команд; `/compact`, `/review`, `/skills`, `/mcp` отображаются на запросы app-server. |
| — | `/model`, `/effort`, `/mode`, `/rename`, `/new`, `/status`, `/clear`, `/stop`, `/help` | Команды платформы, обрабатываемые в браузере или очередью. |

Запросы разрешений, которые CLI задал бы в терминале, появляются на странице: разрешите один раз или откажите, и то же выполнение продолжится. Автоматический режим — собственный режим CLI (Claude `auto`, Codex `auto_review`); Studiolo никогда не добавляет флаги обхода или постоянные правила разрешения. Effort рассуждений и модель можно менять для каждого сообщения в рамках разговора (Claude `set_model` / `apply_flag_settings`, параметры Codex `turn/start`).

## Несколько машин

Запустите один и тот же сервер на каждом компьютере; поместите `projects/` в синхронизируемую папку (Syncthing или любая синхронизация файлов). `.studio/events/` каждого проекта — неизменяемый журнал с причинным порядком; машины, находящиеся в сети, также обмениваются журналами напрямую, так что изменения появляются в течение секунд. Любая машина может показать каждый разговор; выполнение всегда происходит на машине, к которой привязан разговор, а нативные сессии CLI никогда не мигрируют.

**Доступ к другим машинам.** Самая простая безопасная схема — [Tailscale](https://tailscale.com): положите `tailnet.json` (`{"enabled":true,"command":"tailscale"}`) и случайный `access-token.txt` (≥ 32 символов) в каталог состояния, запустите как обычно, и Studiolo опубликует свой порт через `tailscale serve`; откройте `http://<machine>:4310` и один раз введите токен. С `"trustTailnet":true` токен для трафика tailnet не запрашивается. Без Tailscale привяжитесь к приватному адресу через `STUDIO_BIND` и задайте `STUDIO_TOKEN`. Серверы находят друг друга через `projects/.servers/` или ручное сопряжение в Settings.

**Автозапуск.** macOS: `node scripts/install-studio-macos.mjs` устанавливает LaunchAgent (`net.studio-local.server`). Windows: зарегистрируйте `scripts/start-studio-windows.ps1` как задачу Task Scheduler (действие `conhost.exe --headless powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -File <path>`, запуск при входе в систему, без дублирующих экземпляров, повтор каждую минуту); `scripts/restart-studio-windows.ps1` перезапускает её после обновления, как только не останется активных запусков.

**Обновление.** Фронтенд-файлы в `public/` читаются при каждом запросе и вступают в силу сразу после синхронизации; изменения в `src/` требуют перезапуска на каждой машине.

## Artifacts и комментарии на странице

Попросите агента сделать веб-страницу или приложение, и он будет вести `studio.artifacts.json` в корне проекта:

```json
{
  "artifacts": [
    { "key": "game", "name": "Click the target", "root": "game", "entry": "index.html",
      "command": ["node", "server.mjs"], "port": 4320, "dataPaths": ["game/data"] }
  ]
}
```

Статические страницы опускают `command`, `port` и `dataPaths`. Каждый Artifact получает собственный постоянный порт превью и origin; `localStorage` превью сохраняется в проект и синхронизируется, так что игра, сохранённая на одной машине, продолжается на другой. Бэкенды работают как обычные локальные процессы (не в песочнице) с `PORT` и `HOST`; **Snapshot** останавливает бэкенд и копирует объявленные пути данных, **Restore** возвращает их на место.

В превью *выделите элемент, текст или область canvas* и напишите комментарий: он становится задачей для выбранного вами агента, а выделение служит доказательством (путь DOM, цитируемый текст или PNG области canvas). Комментарии к одному Artifact выполняются по порядку; разные Artifacts и разговоры выполняются параллельно. См. `examples/persistent-game/` (бэкенд на Node + SQLite + Canvas) и `examples/artifact-compatibility/`.

## Файлы и конфигурация

| Расположение | Содержимое |
| --- | --- |
| `projects/<id>/` | Рабочий каталог проекта: код, Artifacts, данные (синхронизируется) |
| `projects/<id>/.studio/events/` | Авторитетный неизменяемый журнал разговоров |
| `projects/<id>/.studio/state.json`, `history-index.md`, `sessions/`, `artifacts/` | Восстанавливаемое состояние и читаемая история для агентов |
| `projects/<id>/.studio/artifact-storage/`, `snapshots/`, `attachments/` | Синхронизируемое хранилище превью, снимки данных, доказательства комментариев |
| `projects/<id>/uploads/` | Файлы, перетащенные в чат или панель ресурсов |
| `projects/.servers/` | Публичные адреса серверов для обнаружения (без секретов) |
| `projects/.deleted/<id>.json` | Надгробия удалённых проектов (синхронизируются); папка, воссозданная запоздалой синхронизацией, удаляется снова |
| `~/.studio-local/` | Приватное для машины: идентичность, `accounts.json`, `accounts/<id>/`, сопряжение, настройки Tailscale — никогда не синхронизируйте |
| `~/.studio-local/agent-profiles.json` | Необязательно: путь к исполняемому файлу / env для каждого семейства CLI (`claude`, `codex`) или для id аккаунта |

Удаление проекта необратимо (архивирование остаётся обратимым) и отклоняется, пока работа стоит в очереди, выполняется или ожидает. Удаляющий сервер записывает надгробие, затем удаляет всю папку `projects/<id>/`; ваш инструмент синхронизации переносит и то и другое на остальные машины. Каждый сервер, увидев новое надгробие, удаляет свою оставшуюся копию, резидентные процессы агентов проекта и порты превью Artifacts, а также транскрипты Claude (`projects/<encoded path>*` в каждом каталоге конфигурации) и rollouts Codex (сопоставляются по `cwd` в первой строке), рабочий каталог которых находился внутри проекта. Обработанные ID записываются в `~/.studio-local/purged-projects.json`. Проекты, мягко удалённые старыми версиями (`deletedAt`), удаляются один раз при запуске.

## Частые вопросы

**Использует ли он мой API-ключ?** Только если вы добавите аккаунт с API-ключом. Аккаунты по подписке работают через собственный вход CLI; Studiolo не хранит никаких собственных учётных данных.

**Повлияет ли это на мои `claude` / `codex` в терминале?** Нет. Аккаунты Studiolo живут в собственных каталогах; `~/.claude` и `~/.codex` читаются лишь один раз, чтобы скопировать настройки и создать ссылки на skills.

**Это песочница?** Нет. Агенты и бэкенды Artifacts — ваши собственные локальные процессы с вашими правами, точно как CLI в терминале.

**Можно ли пользоваться с телефона?** Да, как браузерным клиентом через Tailscale; CLI работают на ваших компьютерах.

**Почему ноль зависимостей?** Сервер написан на чистом Node.js (ESM, только модули `node:`), поэтому он работает везде, где работает Node 22, и ничто из цепочки поставок не стоит между вами и вашими CLI.
