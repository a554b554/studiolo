# Studiolo

### Ένας πάγκος εργασίας για κάθε CLI πράκτορα κώδικα που πληρώνετε, σε κάθε μηχάνημα που έχετε.

**Συνομιλήστε με το Claude Code και το Codex από τον browser, με τους λογαριασμούς, τα μηχανήματα και το ιστορικό των έργων κοινά σε όλους τους υπολογιστές σας.**

## Εγκατάσταση με πράκτορα κώδικα

Επικολλήστε το παρακάτω στο Claude Code, στο Codex ή σε οποιονδήποτε πράκτορα κώδικα μπορεί να εκτελεί εντολές στο μηχάνημα που θέλετε να χρησιμοποιήσετε:

```text
Εγκατάστησε το Studiolo από το https://github.com/a554b554/studiolo: κάνε clone το αποθετήριο, βεβαιώσου ότι υπάρχει Node.js 22.14+ και ότι είναι εγκατεστημένα τα CLI `claude` ή/και `codex`, εκτέλεσε `node src/server.mjs` από τη ρίζα του αποθετηρίου, επιβεβαίωσε ότι το http://127.0.0.1:4310 απαντά και μετά πες μου να ανοίξω Settings → Hosts & accounts για να συνδεθώ στους λογαριασμούς μου. Μη συνδεθείς μόνος σου σε τίποτα.
```

Ή χειροκίνητα:

```sh
git clone https://github.com/a554b554/studiolo studiolo && cd studiolo
node src/server.mjs        # http://127.0.0.1:4310
```

Το Studiolo δεν έχει εξαρτήσεις npm· το `npm install` δεν χρειάζεται. Δοκιμές: `node --test test/*.test.mjs`.

## Τι είναι

Το Studiolo είναι ένας αυτο-φιλοξενούμενος πάγκος εργασίας web που οδηγεί τα CLI **Claude Code** και **Codex** που είναι ήδη εγκατεστημένα στους υπολογιστές σας. Δεν είναι άλλο ένα UI συνομιλίας πάνω από ένα κλειδί API:

- **Οι συνδρομές σας, τα CLI σας.** Κάθε αίτημα εκτελείται μέσα από την πραγματική διεργασία `claude` ή `codex`: ίδια εργαλεία, skills, διακομιστές MCP, λειτουργίες αδειών και συμπεριφορά πράκτορα με το τερματικό. Σύνδεση με συνδρομή ή κλειδί API, επιλογή σας για κάθε λογαριασμό.
- **Λογαριασμοί ανά μηχάνημα, υπό τη διαχείριση του Studiolo.** Συνδέστε πολλούς λογαριασμούς Claude και Codex σε κάθε υπολογιστή από τον browser. Κάθε λογαριασμός αποκτά δικό του απομονωμένο κατάλογο ρυθμίσεων CLI· τα προσωπικά σας `~/.claude` ή `~/.codex` δεν αγγίζονται. Το όριο χρήσης κάθε λογαριασμού εμφανίζεται ζωντανά.
- **Ένα ιστορικό έργων σε όλα τα μηχανήματα.** Τα έργα βρίσκονται σε έναν φάκελο που συγχρονίζετε με όποιον τρόπο θέλετε (για παράδειγμα Syncthing). Το ιστορικό συνομιλιών είναι ένα ημερολόγιο μόνο-προσθήκης που συγχωνεύεται ντετερμινιστικά· κάθε μηχάνημα τρέχει τον ίδιο διακομιστή και σερβίρει το ίδιο ιστορικό. Μια συνομιλία εκτελείται στο μηχάνημα που επιλέξατε γι' αυτήν· μπορείτε να τη διαβάσετε και να τη συνεχίσετε από οποιοδήποτε.
- **Η εμπειρία του τερματικού, στον browser.** Σταματήστε έναν γύρο με Esc, κατευθύνετε έναν πράκτορα που τρέχει με ένα επόμενο μήνυμα, πληκτρολογήστε `/` για τις δικές slash εντολές του CLI· όλα αντιστοιχίζονται στα εγγενή πρωτόκολλα, δεν υλοποιούνται ξανά.
- **Artifacts και σχόλια στη σελίδα.** Οι εφαρμογές web που φτιάχνουν οι πράκτορες τρέχουν ως Artifacts με μόνιμα backends και συγχρονισμένη αποθήκευση· επιλέξτε κάτι στην προεπισκόπηση και στείλτε το σε έναν πράκτορα ως εργασία.

## Γρήγορη εκκίνηση

1. **Προαπαιτούμενα**: Node.js 22.14+ και το CLI `claude` ή/και `codex` εγκατεστημένο στο μηχάνημα (`claude --version`, `codex --version`).
2. **Εκτελέστε** `node src/server.mjs` και ανοίξτε το <http://127.0.0.1:4310>.
3. **Προσθέστε λογαριασμούς**: Settings → *Hosts & accounts* → *Add account*. Επιλέξτε το μηχάνημα, τον τύπο (Claude Code / Codex) και τη μέθοδο σύνδεσης και ακολουθήστε τα βήματα που εμφανίζονται (δείτε παρακάτω).
4. **Δημιουργήστε ένα έργο, ξεκινήστε μια συνομιλία**: το πεδίο σύνταξης επιλέγει **μηχάνημα → λογαριασμό → μοντέλο → effort → λειτουργία αδειών**. Το πρώτο μήνυμα ορίζει οριστικά μηχάνημα, λογαριασμό και μοντέλο για τη συνομιλία· το effort και οι άδειες μπορούν να αλλάζουν ανά μήνυμα.

Μεταβλητές περιβάλλοντος: `STUDIO_STATE_DIR` (ιδιωτική κατάσταση του μηχανήματος, προεπιλογή `~/.studio-local`), `STUDIO_BIND`, `STUDIO_PORT` (4310), `STUDIO_PREVIEW_PORT` (4311), `STUDIO_TOKEN`, `STUDIO_UPLOAD_LIMIT` (bytes, προεπιλογή 100 MB). Ένας διακομιστής ανά κατάλογο κατάστασης.

## Λογαριασμοί και σύνδεση

Οι λογαριασμοί ανήκουν σε ένα μηχάνημα και δημιουργούνται από τον browser. Κάθε λογαριασμός είναι ένας κατάλογος κάτω από το `~/.studio-local/accounts/<id>/`, που χρησιμοποιείται ως `CLAUDE_CONFIG_DIR` ή `CODEX_HOME`, ώστε πολλοί λογαριασμοί του ίδιου CLI να συνυπάρχουν και η σύνδεση του δικού σας τερματικού να μην αγγίζεται ποτέ. Όταν δημιουργείται ένας λογαριασμός, το Studiolo αρχικοποιεί αυτόν τον κατάλογο από τον προεπιλεγμένο κατάλογο του CLI σας: αντιγράφει τα `settings.json` / `CLAUDE.md` (Codex: `config.toml` / `AGENTS.md`) και δημιουργεί συνδέσμους για τα `skills`, `plugins` και τα συναφή, ώστε οι πράκτορες να κρατούν τα skills και τους διακομιστές MCP που ήδη χρησιμοποιείτε. Τα διαπιστευτήρια δεν αντιγράφονται ποτέ.

| Τύπος | Μέθοδος | Τι συμβαίνει |
| --- | --- | --- |
| Claude Code | **Συνδρομή** | Το Studiolo εκτελεί `claude auth login`· ανοίγετε τον σύνδεσμο, συνδέεστε και επικολλάτε τον κωδικό εξουσιοδότησης πίσω στη σελίδα. |
| Claude Code | **Κλειδί Anthropic API** | Το κλειδί αποθηκεύεται στον κατάλογο του λογαριασμού (mode 0600) και περνά ως `ANTHROPIC_API_KEY`· επαληθεύεται μέσω του handshake του CLI και απορρίπτεται αν δεν γίνει δεκτό. Πληρωμή ανά χρήση, χωρίς παράθυρα ορίων. |
| Codex | **ChatGPT** | Κωδικός συσκευής μέσω του app-server του Codex: η σελίδα δείχνει έναν σύνδεσμο και έναν κωδικό μίας χρήσης· συνδεθείτε από οποιονδήποτε browser και η σελίδα ενημερώνεται όταν ολοκληρωθεί. |
| Codex | **Κλειδί OpenAI API** | Αποθηκεύεται από το ίδιο το Codex στο `CODEX_HOME` του λογαριασμού. |

Μετά τη σύνδεση, το Studiolo διαβάζει την ταυτότητα του λογαριασμού (e-mail, πρόγραμμα) και τη λίστα μοντέλων απευθείας από το CLI, χωρίς να ξοδεύει κανένα αίτημα μοντέλου, και, για το Claude, τις slash εντολές του CLI για την αυτόματη συμπλήρωση στο πεδίο σύνταξης. Ένας λογαριασμός χωρίς προσαρμοσμένο όνομα μετονομάζεται στο e-mail του, ώστε το πεδίο σύνταξης, η κεφαλίδα της συνομιλίας, κάθε απάντηση και ο πίνακας χρήσης να δείχνουν ποιος μιλά. Οι λογαριασμοί μπορούν να μετονομαστούν, να ανανεωθούν, να αποσυνδεθούν (`claude auth logout` / `codex logout`) ή να αφαιρεθούν· μια συνομιλία της οποίας ο λογαριασμός αφαιρέθηκε μπορεί να συνεχιστεί με άλλον λογαριασμό στο ίδιο μηχάνημα.

Ο πίνακας χρήσης (κάτω αριστερά) ακολουθεί το μηχάνημα που επιλέχθηκε στο πεδίο σύνταξης: οι συνδρομές Claude δείχνουν το παράθυρο 5 ωρών, το Codex το εβδομαδιαίο, οι λογαριασμοί με κλειδί API χρεώνονται ανά χρήση. Διαβάζει τα δικά endpoints χρήσης των CLI (`get_usage`, `account/rateLimits/read`), κρατά cache για 60 s, δεν κάνει ποτέ polling και δεν ξεκινά ποτέ CLI για αποσυνδεδεμένο λογαριασμό.

Όλα αυτά λειτουργούν και για απομακρυσμένα μηχανήματα: επιλέξτε έναν άλλον συνδεδεμένο host στο *Hosts & accounts* και τα αιτήματα προωθούνται σε αυτόν.

## Συνομιλία όπως στο CLI

Κάθε συνομιλία έχει μια μόνιμη εγγενή διεργασία, το Claude Code μέσω αμφίδρομου `stream-json`, το Codex μέσω `app-server`, ώστε ο πράκτορας να συμπεριφέρεται ακριβώς όπως στο τερματικό. Τα χειριστήρια του web αντιστοιχίζονται στα εγγενή πρωτόκολλα:

| Στο τερματικό | Στο Studiolo | Πώς |
| --- | --- | --- |
| Esc για διακοπή | **■ Stop** ή Esc στο πεδίο σύνταξης | Αίτημα ελέγχου `interrupt` στο Claude / `turn/interrupt` στο Codex. Η διεργασία και η εγγενής συνεδρία επιβιώνουν· η μερική απάντηση διατηρείται· τα επόμενα μηνύματα συνεχίζουν την ίδια συνεδρία. |
| Πληκτρολόγηση ενώ ο πράκτορας δουλεύει | Αποστολή ενώ τρέχει ένας γύρος = **Steer** | Το Claude το διαβάζει στο επόμενο όριο εργαλείου· στο Codex `turn/steer`. Εμφανίζεται ως *You · steer*· η απάντηση συνεχίζει σε νέο τμήμα. Το **Queue** αντίθετα στέλνει μετά τον γύρο. |
| `/compact`, `/context`, προσαρμοσμένες εντολές, skills | Πληκτρολογήστε `/` για τη λίστα εντολών | Οι εντολές του Claude περνούν αυτούσιες (η λίστα προέρχεται από το ίδιο το CLI). Το Codex δεν έχει εντολές κειμένου· τα `/compact`, `/review`, `/skills`, `/mcp` αντιστοιχίζονται σε αιτήματα app-server. |
| — | `/model`, `/effort`, `/mode`, `/rename`, `/new`, `/status`, `/clear`, `/stop`, `/help` | Εντολές της πλατφόρμας που χειρίζεται ο browser ή η ουρά. |

Τα αιτήματα αδειών που το CLI θα ρωτούσε στο τερματικό εμφανίζονται στη σελίδα: εγκρίνετε μία φορά ή αρνηθείτε, και η ίδια εκτέλεση συνεχίζεται. Η αυτόματη λειτουργία είναι αυτή του ίδιου του CLI (Claude `auto`, Codex `auto_review`)· το Studiolo δεν προσθέτει ποτέ σημαίες παράκαμψης ή μόνιμους κανόνες έγκρισης. Το effort συλλογισμού και το μοντέλο μπορούν να αλλάζουν ανά μήνυμα μέσα σε μια συνομιλία (Claude `set_model` / `apply_flag_settings`, παράμετροι `turn/start` στο Codex).

## Πολλαπλά μηχανήματα

Τρέξτε τον ίδιο διακομιστή σε κάθε υπολογιστή· βάλτε το `projects/` σε έναν φάκελο που συγχρονίζετε (Syncthing ή οποιοδήποτε εργαλείο συγχρονισμού αρχείων). Το `.studio/events/` κάθε έργου είναι ένα αμετάβλητο ημερολόγιο με αιτιακή σειρά· τα μηχανήματα που είναι online ανταλλάσσουν επίσης ημερολόγια απευθείας, ώστε οι αλλαγές να εμφανίζονται μέσα σε δευτερόλεπτα. Οποιοδήποτε μηχάνημα μπορεί να δείξει κάθε συνομιλία· η εκτέλεση γίνεται πάντα στο μηχάνημα στο οποίο είναι δεμένη η συνομιλία, και οι εγγενείς συνεδρίες CLI δεν μεταφέρονται ποτέ.

**Πρόσβαση σε άλλα μηχανήματα.** Η απλούστερη ασφαλής διαμόρφωση είναι το [Tailscale](https://tailscale.com): βάλτε ένα `tailnet.json` (`{"enabled":true,"command":"tailscale"}`) και ένα τυχαίο `access-token.txt` (≥ 32 χαρακτήρες) στον κατάλογο κατάστασης, ξεκινήστε κανονικά, και το Studiolo δημοσιεύει τη θύρα του με `tailscale serve`· ανοίξτε το `http://<machine>:4310` και εισαγάγετε το token μία φορά. Με `"trustTailnet":true` το token παραλείπεται για κίνηση από το tailnet. Χωρίς Tailscale, κάντε bind σε ιδιωτική διεύθυνση με `STUDIO_BIND` και ορίστε `STUDIO_TOKEN`. Οι διακομιστές ανακαλύπτουν ο ένας τον άλλον μέσω του `projects/.servers/` ή με χειροκίνητη σύζευξη στις Settings.

**Αυτόματη εκκίνηση.** macOS: το `node scripts/install-studio-macos.mjs` εγκαθιστά ένα LaunchAgent (`net.studio-local.server`). Windows: καταχωρίστε το `scripts/start-studio-windows.ps1` ως εργασία του Task Scheduler (ενέργεια `conhost.exe --headless powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -File <path>`, εκτέλεση κατά τη σύνδεση, χωρίς διπλά στιγμιότυπα, επανάληψη κάθε λεπτό)· το `scripts/restart-studio-windows.ps1` το επανεκκινεί μετά από αναβάθμιση μόλις δεν υπάρχουν ενεργές εκτελέσεις.

**Αναβάθμιση.** Τα αρχεία front-end κάτω από το `public/` διαβάζονται σε κάθε αίτημα και ισχύουν μόλις συγχρονιστούν· οι αλλαγές κάτω από το `src/` χρειάζονται επανεκκίνηση σε κάθε μηχάνημα.

## Artifacts και σχόλια στη σελίδα

Ζητήστε από έναν πράκτορα μια ιστοσελίδα ή εφαρμογή και θα συντηρεί το `studio.artifacts.json` στη ρίζα του έργου:

```json
{
  "artifacts": [
    { "key": "game", "name": "Click the target", "root": "game", "entry": "index.html",
      "command": ["node", "server.mjs"], "port": 4320, "dataPaths": ["game/data"] }
  ]
}
```

Οι στατικές σελίδες παραλείπουν τα `command`, `port` και `dataPaths`. Κάθε Artifact αποκτά δική του μόνιμη θύρα προεπισκόπησης και origin· το `localStorage` της προεπισκόπησης αποθηκεύεται μέσα στο έργο και συγχρονίζεται, ώστε ένα παιχνίδι που αποθηκεύτηκε σε ένα μηχάνημα να συνεχίζει σε άλλο. Τα backends τρέχουν ως απλές τοπικές διεργασίες (όχι sandbox) με `PORT` και `HOST`· το **Snapshot** σταματά το backend και αντιγράφει τις δηλωμένες διαδρομές δεδομένων, το **Restore** τις επαναφέρει.

Στην προεπισκόπηση, *επιλέξτε ένα στοιχείο, κείμενο ή μια περιοχή του canvas* και γράψτε ένα σχόλιο: γίνεται εργασία για τον πράκτορα που επιλέγετε, με την επιλογή ως τεκμήριο (διαδρομή DOM, παρατιθέμενο κείμενο ή PNG του canvas). Τα σχόλια σε ένα Artifact εκτελούνται με σειρά· διαφορετικά Artifacts και συνομιλίες εκτελούνται παράλληλα. Δείτε τα `examples/persistent-game/` (backend Node + SQLite + Canvas) και `examples/artifact-compatibility/`.

## Αρχεία και ρυθμίσεις

| Τοποθεσία | Περιεχόμενο |
| --- | --- |
| `projects/<id>/` | Κατάλογος εργασίας του έργου: κώδικας, Artifacts, δεδομένα (συγχρονισμένα) |
| `projects/<id>/.studio/events/` | Το έγκυρο, αμετάβλητο ημερολόγιο συνομιλιών |
| `projects/<id>/.studio/state.json`, `history-index.md`, `sessions/`, `artifacts/` | Κατάσταση που μπορεί να ανακατασκευαστεί και αναγνώσιμο ιστορικό για τους πράκτορες |
| `projects/<id>/.studio/artifact-storage/`, `snapshots/`, `attachments/` | Συγχρονισμένη αποθήκευση προεπισκόπησης, στιγμιότυπα δεδομένων, τεκμήρια σχολίων |
| `projects/<id>/uploads/` | Αρχεία που ρίχνονται στη συνομιλία ή στον πίνακα πόρων |
| `projects/.servers/` | Δημόσιες διευθύνσεις διακομιστών για ανακάλυψη (χωρίς μυστικά) |
| `projects/.deleted/<id>.json` | Ταφόπλακες (tombstones) διαγραμμένων έργων (συγχρονισμένες)· ένας φάκελος που ξαναδημιουργείται από καθυστερημένο συγχρονισμό αφαιρείται ξανά |
| `~/.studio-local/` | Ιδιωτικό για το μηχάνημα: ταυτότητα, `accounts.json`, `accounts/<id>/`, σύζευξη, ρυθμίσεις Tailscale· μην το συγχρονίζετε ποτέ |
| `~/.studio-local/agent-profiles.json` | Προαιρετικό: διαδρομή εκτελέσιμου / env ανά οικογένεια CLI (`claude`, `codex`) ή ανά id λογαριασμού |

Η διαγραφή ενός έργου είναι οριστική (η αρχειοθέτηση παραμένει αναστρέψιμη) και απορρίπτεται όσο υπάρχει εργασία σε ουρά, σε εκτέλεση ή σε αναμονή. Ο διακομιστής που διαγράφει γράφει μια ταφόπλακα και μετά αφαιρεί ολόκληρο τον φάκελο `projects/<id>/`· το εργαλείο συγχρονισμού σας μεταφέρει και τα δύο στα άλλα μηχανήματα. Κάθε διακομιστής, όταν βλέπει μια νέα ταφόπλακα, αφαιρεί το υπόλοιπο αντίγραφό του, τις μόνιμες διεργασίες πρακτόρων του έργου και τις θύρες προεπισκόπησης των Artifacts, καθώς και τα transcripts του Claude (`projects/<encoded path>*` σε κάθε κατάλογο ρυθμίσεων) και τα rollouts του Codex (που αντιστοιχίζονται μέσω του `cwd` στην πρώτη τους γραμμή) των οποίων ο κατάλογος εργασίας βρισκόταν μέσα στο έργο. Τα IDs που έχουν διεκπεραιωθεί καταγράφονται στο `~/.studio-local/purged-projects.json`. Τα έργα που είχαν διαγραφεί «ήπια» από παλαιότερες εκδόσεις (`deletedAt`) αφαιρούνται μία φορά κατά την εκκίνηση.

## Συχνές ερωτήσεις

**Χρησιμοποιεί το κλειδί API μου;** Μόνο αν προσθέσετε λογαριασμό με κλειδί API. Οι λογαριασμοί συνδρομής λειτουργούν μέσω της δικής σύνδεσης των CLI· το Studiolo δεν αποθηκεύει δικά του διαπιστευτήρια.

**Θα επηρεαστεί το `claude` / `codex` του τερματικού μου;** Όχι. Οι λογαριασμοί του Studiolo βρίσκονται στους δικούς τους καταλόγους· τα `~/.claude` και `~/.codex` διαβάζονται μόνο μία φορά για να αντιγραφούν οι ρυθμίσεις και να συνδεθούν τα skills.

**Είναι sandbox;** Όχι. Οι πράκτορες και τα backends των Artifacts είναι δικές σας τοπικές διεργασίες με τις δικές σας άδειες, ακριβώς όπως τα CLI σε ένα τερματικό.

**Μπορώ να το χρησιμοποιήσω από το κινητό μου;** Ναι, ως πελάτη browser μέσω Tailscale· τα CLI τρέχουν στους υπολογιστές σας.

**Γιατί μηδέν εξαρτήσεις;** Ο διακομιστής είναι καθαρό Node.js (ESM, μόνο modules `node:`), ώστε να τρέχει οπουδήποτε τρέχει το Node 22 και τίποτα από την αλυσίδα εφοδιασμού να μη βρίσκεται ανάμεσα σε εσάς και τα CLI σας.
