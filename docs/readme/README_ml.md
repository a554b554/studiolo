## കോഡിങ് ഏജന്റ് ഉപയോഗിച്ച് ഇൻസ്റ്റാൾ ചെയ്യുക

നിങ്ങൾ ഉപയോഗിക്കാൻ ഉദ്ദേശിക്കുന്ന മെഷീനിൽ കമാൻഡുകൾ റൺ ചെയ്യാൻ കഴിയുന്ന Claude Code, Codex അല്ലെങ്കിൽ ഏതെങ്കിലും കോഡിങ് ഏജന്റിലേക്ക് ഇത് പേസ്റ്റ് ചെയ്യുക:

```text
https://github.com/a554b554/studiolo എന്നതിൽ നിന്ന് Studiolo ഇൻസ്റ്റാൾ ചെയ്യുക: റിപ്പോസിറ്ററി clone ചെയ്യുക, Node.js 22.14+ ലഭ്യമാണെന്നും `claude` കൂടാതെ/അല്ലെങ്കിൽ `codex` CLI-കൾ ഇൻസ്റ്റാൾ ചെയ്തിട്ടുണ്ടെന്നും ഉറപ്പാക്കുക, റിപ്പോസിറ്ററിയുടെ റൂട്ടിൽ നിന്ന് `node src/server.mjs` റൺ ചെയ്യുക, http://127.0.0.1:4310 പ്രതികരിക്കുന്നുണ്ടെന്ന് സ്ഥിരീകരിക്കുക, തുടർന്ന് എന്റെ അക്കൗണ്ടുകളിൽ സൈൻ ഇൻ ചെയ്യാൻ Settings → Hosts & accounts തുറക്കാൻ എന്നോട് പറയുക. നിങ്ങൾ സ്വയം ഒന്നിലും സൈൻ ഇൻ ചെയ്യരുത്.
```

അല്ലെങ്കിൽ സ്വമേധയാ:

```sh
git clone https://github.com/a554b554/studiolo studiolo && cd studiolo
node src/server.mjs        # http://127.0.0.1:4310
```

Studiolo-യ്ക്ക് npm ഡിപൻഡൻസികൾ ഒന്നുമില്ല; `npm install` ആവശ്യമില്ല. ടെസ്റ്റുകൾ: `node --test test/*.test.mjs`.

## Studiolo എന്താണ്

നിങ്ങളുടെ കമ്പ്യൂട്ടറുകളിൽ ഇതിനകം ഇൻസ്റ്റാൾ ചെയ്തിട്ടുള്ള **Claude Code**, **Codex** CLI-കളെ പ്രവർത്തിപ്പിക്കുന്ന, സ്വയം ഹോസ്റ്റ് ചെയ്യുന്ന ഒരു വെബ് വർക്ക്ബെഞ്ചാണ് Studiolo. ഇത് ഒരു API കീയ്ക്ക് മുകളിലുള്ള മറ്റൊരു ചാറ്റ് UI അല്ല:

- **നിങ്ങളുടെ സബ്സ്ക്രിപ്ഷനുകൾ, നിങ്ങളുടെ CLI-കൾ.** ഓരോ അഭ്യർത്ഥനയും യഥാർത്ഥ `claude` അല്ലെങ്കിൽ `codex` പ്രോസസിലൂടെയാണ് പ്രവർത്തിക്കുന്നത്: ടെർമിനലിലേതുപോലെ തന്നെയുള്ള ടൂളുകൾ, skills, MCP സെർവറുകൾ, പെർമിഷൻ മോഡുകൾ, ഏജന്റ് പെരുമാറ്റം. സബ്സ്ക്രിപ്ഷൻ സൈൻ ഇൻ അല്ലെങ്കിൽ API കീ, ഓരോ അക്കൗണ്ടിനും നിങ്ങൾക്ക് തിരഞ്ഞെടുക്കാം.
- **ഓരോ മെഷീനിനും അക്കൗണ്ടുകൾ, Studiolo കൈകാര്യം ചെയ്യുന്നു.** ഓരോ കമ്പ്യൂട്ടറിലും ബ്രൗസറിൽ നിന്ന് ഒന്നിലധികം Claude, Codex അക്കൗണ്ടുകളിൽ സൈൻ ഇൻ ചെയ്യുക. ഓരോ അക്കൗണ്ടിനും സ്വന്തം ഒറ്റപ്പെട്ട CLI കോൺഫിഗറേഷൻ ഡയറക്ടറി ലഭിക്കുന്നു; നിങ്ങളുടെ സ്വകാര്യ `~/.claude`, `~/.codex` എന്നിവയെ ഒന്നും സ്പർശിക്കുന്നില്ല. ഓരോ അക്കൗണ്ടിന്റെയും ക്വോട്ട തത്സമയം കാണിക്കുന്നു.
- **എല്ലാ മെഷീനുകളിലും ഒരൊറ്റ പ്രോജക്റ്റ് ചരിത്രം.** പ്രോജക്റ്റുകൾ നിങ്ങൾക്കിഷ്ടമുള്ള രീതിയിൽ സിങ്ക് ചെയ്യുന്ന ഒരു ഫോൾഡറിലാണ് (ഉദാഹരണത്തിന് Syncthing). സംഭാഷണ ചരിത്രം append-only ആയ ഒരു ജേണലാണ്, അത് നിർണ്ണായകമായി ലയിക്കുന്നു; ഓരോ മെഷീനും ഒരേ സെർവർ റൺ ചെയ്യുകയും ഒരേ ചരിത്രം നൽകുകയും ചെയ്യുന്നു. ഒരു സംഭാഷണം നിങ്ങൾ അതിനായി തിരഞ്ഞെടുത്ത മെഷീനിലാണ് പ്രവർത്തിക്കുന്നത്; ഏത് മെഷീനിൽ നിന്നും അത് വായിക്കാനും തുടരാനും കഴിയും.
- **ടെർമിനൽ അനുഭവം, ബ്രൗസറിൽ.** Esc ഉപയോഗിച്ച് ഒരു ടേൺ നിർത്തുക, പ്രവർത്തിച്ചുകൊണ്ടിരിക്കുന്ന ഏജന്റിനെ ഒരു തുടർ സന്ദേശം വഴി നയിക്കുക, CLI-യുടെ സ്വന്തം slash കമാൻഡുകൾക്കായി `/` ടൈപ്പ് ചെയ്യുക; ഇവയെല്ലാം നേറ്റീവ് പ്രോട്ടോക്കോളുകളിലേക്ക് മാപ്പ് ചെയ്തിരിക്കുന്നു, വീണ്ടും നടപ്പിലാക്കിയതല്ല.
- **Artifacts, പേജിലെ കമന്റുകൾ.** ഏജന്റുകൾ നിർമ്മിക്കുന്ന വെബ് ആപ്പുകൾ സ്ഥിരമായ ബാക്കെൻഡുകളും സിങ്ക് ചെയ്ത സ്റ്റോറേജുമുള്ള Artifacts ആയി പ്രവർത്തിക്കുന്നു; പ്രിവ്യൂവിൽ എന്തെങ്കിലും തിരഞ്ഞെടുത്ത് ഒരു ടാസ്കായി ഏജന്റിന് അയയ്ക്കുക.

## വേഗത്തിൽ തുടങ്ങാം

1. **മുൻവ്യവസ്ഥകൾ**: Node.js 22.14+, കൂടാതെ മെഷീനിൽ ഇൻസ്റ്റാൾ ചെയ്ത `claude` കൂടാതെ/അല്ലെങ്കിൽ `codex` CLI (`claude --version`, `codex --version`).
2. **റൺ ചെയ്യുക** `node src/server.mjs`, തുടർന്ന് <http://127.0.0.1:4310> തുറക്കുക.
3. **അക്കൗണ്ടുകൾ ചേർക്കുക**: Settings → *Hosts & accounts* → *Add account*. മെഷീൻ, തരം (Claude Code / Codex), സൈൻ ഇൻ രീതി എന്നിവ തിരഞ്ഞെടുത്ത് കാണിക്കുന്ന ഘട്ടങ്ങൾ പിന്തുടരുക (താഴെ കാണുക).
4. **ഒരു പ്രോജക്റ്റ് സൃഷ്ടിച്ച് സംഭാഷണം തുടങ്ങുക**: കമ്പോസർ **മെഷീൻ → അക്കൗണ്ട് → മോഡൽ → effort → പെർമിഷൻ മോഡ്** എന്നിവ തിരഞ്ഞെടുക്കുന്നു. ആദ്യ സന്ദേശം ആ സംഭാഷണത്തിനുള്ള മെഷീനും അക്കൗണ്ടും ഉറപ്പിക്കുന്നു; മോഡൽ, effort, പെർമിഷനുകൾ എന്നിവ ഓരോ സന്ദേശത്തിലും മാറ്റാം. മറ്റൊരു മോഡൽ അതേ നേറ്റീവ് സെഷൻ തുടരുന്നു; അതിന്റെ ആദ്യ ടേൺ പ്രോംപ്റ്റ് കാഷെ ഇല്ലാതെ സന്ദർഭം വീണ്ടും വായിക്കുന്നു.

എൻവയോൺമെന്റ് വേരിയബിളുകൾ: `STUDIO_STATE_DIR` (മെഷീന്റെ സ്വകാര്യ സ്റ്റേറ്റ്, ഡിഫോൾട്ട് `~/.studio-local`), `STUDIO_BIND`, `STUDIO_PORT` (4310), `STUDIO_PREVIEW_PORT` (4311), `STUDIO_TOKEN`, `STUDIO_UPLOAD_LIMIT` (ബൈറ്റുകൾ, ഡിഫോൾട്ട് 100 MB). ഒരു സ്റ്റേറ്റ് ഡയറക്ടറിക്ക് ഒരു സെർവർ.

## അക്കൗണ്ടുകളും ലോഗിനും

അക്കൗണ്ടുകൾ ഒരു മെഷീനിന്റേതാണ്, അവ ബ്രൗസറിൽ നിന്നാണ് സൃഷ്ടിക്കുന്നത്. ഓരോ അക്കൗണ്ടും `~/.studio-local/accounts/<id>/` എന്നതിന് കീഴിലുള്ള ഒരു ഡയറക്ടറിയാണ്, അത് `CLAUDE_CONFIG_DIR` അല്ലെങ്കിൽ `CODEX_HOME` ആയി ഉപയോഗിക്കുന്നു; അതിനാൽ ഒരു CLI-യുടെ ഒന്നിലധികം അക്കൗണ്ടുകൾ ഒരുമിച്ച് നിലനിൽക്കുന്നു, നിങ്ങളുടെ ടെർമിനലിന്റെ സ്വന്തം സൈൻ ഇൻ ഒരിക്കലും സ്പർശിക്കപ്പെടുന്നില്ല. ഒരു അക്കൗണ്ട് സൃഷ്ടിക്കുമ്പോൾ, Studiolo നിങ്ങളുടെ ഡിഫോൾട്ട് CLI ഡയറക്ടറിയിൽ നിന്ന് ആ ഡയറക്ടറി സജ്ജമാക്കുന്നു: `settings.json` / `CLAUDE.md` (Codex: `config.toml` / `AGENTS.md`) പകർത്തുകയും `skills`, `plugins` തുടങ്ങിയവ ലിങ്ക് ചെയ്യുകയും ചെയ്യുന്നു; അതുവഴി നിങ്ങൾ ഇതിനകം ഉപയോഗിക്കുന്ന skills-ഉം MCP സെർവറുകളും ഏജന്റുകൾക്ക് നിലനിൽക്കുന്നു. ക്രെഡൻഷ്യലുകൾ ഒരിക്കലും പകർത്തുന്നില്ല.

സൈൻ ഇൻ ചെയ്ത ശേഷം Studiolo അക്കൗണ്ടിന്റെ ഐഡന്റിറ്റി (ഇ-മെയിൽ, പ്ലാൻ), മോഡൽ ലിസ്റ്റ് എന്നിവ നേരിട്ട് CLI-യിൽ നിന്ന് വായിക്കുന്നു, ഒരു മോഡൽ അഭ്യർത്ഥന പോലും ചെലവാക്കാതെ; Claude-ന്റെ കാര്യത്തിൽ കമ്പോസറിലെ ഓട്ടോകംപ്ലീറ്റിനായി CLI-യുടെ slash കമാൻഡുകളും വായിക്കുന്നു. ഇഷ്ടാനുസൃത പേരില്ലാത്ത അക്കൗണ്ടിന് അതിന്റെ ഇ-മെയിൽ പേരായി നൽകുന്നു; അതുവഴി കമ്പോസറും സംഭാഷണ ഹെഡറും ഓരോ മറുപടിയും ഉപയോഗ പാനലും ആരാണ് സംസാരിക്കുന്നതെന്ന് കാണിക്കുന്നു. അക്കൗണ്ടുകൾ പുനർനാമകരണം ചെയ്യാം, പുതുക്കാം, സൈൻ ഔട്ട് ചെയ്യാം (`claude auth logout` / `codex logout`) അല്ലെങ്കിൽ നീക്കം ചെയ്യാം; അക്കൗണ്ട് നീക്കം ചെയ്യപ്പെട്ട ഒരു സംഭാഷണം അതേ മെഷീനിലെ മറ്റൊരു അക്കൗണ്ട് ഉപയോഗിച്ച് തുടരാം.

ഉപയോഗ പാനൽ (താഴെ ഇടത്) കമ്പോസറിൽ തിരഞ്ഞെടുത്ത മെഷീനെ പിന്തുടരുന്നു: Claude സബ്സ്ക്രിപ്ഷനുകൾ 5 മണിക്കൂർ വിൻഡോയും Codex ആഴ്ചതോറുമുള്ള വിൻഡോയും കാണിക്കുന്നു, API കീ അക്കൗണ്ടുകൾക്ക് ഉപയോഗത്തിനനുസരിച്ച് ബിൽ ചെയ്യുന്നു. ഇത് CLI-കളുടെ സ്വന്തം ഉപയോഗ എൻഡ്പോയിന്റുകൾ (`get_usage`, `account/rateLimits/read`) വായിക്കുന്നു, 60 സെക്കൻഡ് കാഷെ ചെയ്യുന്നു, ഒരിക്കലും പോൾ ചെയ്യുന്നില്ല, സൈൻ ഔട്ട് ചെയ്ത അക്കൗണ്ടിനായി ഒരിക്കലും CLI ആരംഭിക്കുന്നില്ല.

ഇതെല്ലാം റിമോട്ട് മെഷീനുകൾക്കും പ്രവർത്തിക്കും: *Hosts & accounts*-ൽ ഓൺലൈനിലുള്ള മറ്റൊരു ഹോസ്റ്റ് തിരഞ്ഞെടുക്കുക, അഭ്യർത്ഥനകൾ അതിലേക്ക് റിലേ ചെയ്യപ്പെടും.

## CLI പോലെ ചാറ്റ് ചെയ്യാം

ഓരോ സംഭാഷണത്തിനും സ്ഥിരമായി പ്രവർത്തിക്കുന്ന ഒരു നേറ്റീവ് പ്രോസസ് ഉണ്ട്, Claude Code ദ്വിദിശ `stream-json` വഴിയും Codex `app-server` വഴിയും; അതിനാൽ ഏജന്റ് ടെർമിനലിലെന്നപോലെ തന്നെ പെരുമാറുന്നു. വെബ് നിയന്ത്രണങ്ങൾ നേറ്റീവ് പ്രോട്ടോക്കോളുകളിലേക്ക് മാപ്പ് ചെയ്തിരിക്കുന്നു:

| ടെർമിനലിൽ | Studiolo-ൽ | എങ്ങനെ |
| --- | --- | --- |
| നിർത്താൻ Esc | **■ Stop** അല്ലെങ്കിൽ കമ്പോസറിൽ Esc | Claude-ൽ `interrupt` കൺട്രോൾ അഭ്യർത്ഥന / Codex-ൽ `turn/interrupt`. പ്രോസസും നേറ്റീവ് സെഷനും നിലനിൽക്കുന്നു; ഭാഗിക മറുപടി സൂക്ഷിക്കുന്നു; പിന്നീടുള്ള സന്ദേശങ്ങൾ അതേ സെഷൻ തുടരുന്നു. |
| ഏജന്റ് പ്രവർത്തിക്കുമ്പോൾ ടൈപ്പ് ചെയ്യുക | ഒരു ടേൺ നടക്കുമ്പോൾ അയയ്ക്കുന്നത് = **Steer** | അടുത്ത ടൂൾ അതിർത്തിയിൽ Claude അത് വായിക്കുന്നു; Codex-ൽ `turn/steer`. *You · steer* എന്ന് കാണിക്കുന്നു; മറുപടി ഒരു പുതിയ ഭാഗത്തിൽ തുടരുന്നു. **Queue** പകരം ടേൺ കഴിഞ്ഞ ശേഷം അയയ്ക്കുന്നു. |
| `/compact`, `/context`, ഇഷ്ടാനുസൃത കമാൻഡുകൾ, skills | കമാൻഡ് ലിസ്റ്റിനായി `/` ടൈപ്പ് ചെയ്യുക | Claude കമാൻഡുകൾ അതേപടി കടന്നുപോകുന്നു (ലിസ്റ്റ് CLI-യിൽ നിന്ന് തന്നെ വരുന്നു). Codex-ന് ടെക്സ്റ്റ് കമാൻഡുകൾ ഇല്ല; `/compact`, `/review`, `/skills`, `/mcp` എന്നിവ app-server അഭ്യർത്ഥനകളിലേക്ക് മാപ്പ് ചെയ്തിരിക്കുന്നു. |
| — | `/model`, `/effort`, `/mode`, `/rename`, `/new`, `/status`, `/clear`, `/stop`, `/help` | ബ്രൗസറിലോ ക്യൂവിലോ കൈകാര്യം ചെയ്യുന്ന പ്ലാറ്റ്ഫോം കമാൻഡുകൾ. |

CLI ടെർമിനലിൽ ചോദിക്കുമായിരുന്ന പെർമിഷൻ അഭ്യർത്ഥനകൾ പേജിൽ ദൃശ്യമാകുന്നു: ഒരിക്കൽ അംഗീകരിക്കുക അല്ലെങ്കിൽ നിരസിക്കുക, അതേ പ്രവർത്തനം തുടരുന്നു. ഓട്ടോ മോഡ് CLI-യുടെ സ്വന്തമാണ് (Claude `auto`, Codex `auto_review`); Studiolo ഒരിക്കലും ബൈപാസ് ഫ്ലാഗുകളോ സ്ഥിരമായ അനുമതി നിയമങ്ങളോ ചേർക്കുന്നില്ല. ഒരു സംഭാഷണത്തിനുള്ളിൽ ഓരോ സന്ദേശത്തിലും റീസണിങ് effort-ഉം മോഡലും മാറ്റാം (Claude `set_model` / `apply_flag_settings`, Codex `turn/start` പാരാമീറ്ററുകൾ).

## ഒന്നിലധികം മെഷീനുകൾ

എല്ലാ കമ്പ്യൂട്ടറിലും ഒരേ സെർവർ റൺ ചെയ്യുക; `projects/` നിങ്ങൾ സിങ്ക് ചെയ്യുന്ന ഒരു ഫോൾഡറിൽ വയ്ക്കുക (Syncthing അല്ലെങ്കിൽ ഏതെങ്കിലും ഫയൽ സിങ്ക്). ഓരോ പ്രോജക്റ്റിന്റെയും `.studio/events/` മാറ്റമില്ലാത്ത, കാര്യകാരണ ക്രമത്തിലുള്ള ഒരു ജേണലാണ്; ഓൺലൈനിലുള്ള മെഷീനുകൾ ജേണലുകൾ നേരിട്ടും കൈമാറുന്നു, അതിനാൽ മാറ്റങ്ങൾ നിമിഷങ്ങൾക്കുള്ളിൽ ദൃശ്യമാകും. ഏത് മെഷീനും എല്ലാ സംഭാഷണങ്ങളും കാണിക്കാം; എന്നാൽ പ്രവർത്തനം എപ്പോഴും സംഭാഷണം ബന്ധിപ്പിച്ചിരിക്കുന്ന മെഷീനിലാണ് നടക്കുന്നത്, നേറ്റീവ് CLI സെഷനുകൾ ഒരിക്കലും മാറ്റപ്പെടുന്നില്ല.

**മറ്റ് മെഷീനുകളിലേക്ക് എത്താൻ.** ഏറ്റവും ലളിതമായ സുരക്ഷിത സജ്ജീകരണം [Tailscale](https://tailscale.com) ആണ്: `tailnet.json` (`{"enabled":true,"command":"tailscale"}`), ക്രമരഹിതമായ ഒരു `access-token.txt` (≥ 32 അക്ഷരങ്ങൾ) എന്നിവ സ്റ്റേറ്റ് ഡയറക്ടറിയിൽ വയ്ക്കുക, സാധാരണപോലെ ആരംഭിക്കുക; Studiolo `tailscale serve` ഉപയോഗിച്ച് അതിന്റെ പോർട്ട് പ്രസിദ്ധീകരിക്കുന്നു; `http://<machine>:4310` തുറന്ന് ടോക്കൺ ഒരിക്കൽ നൽകുക. `"trustTailnet":true` ആണെങ്കിൽ tailnet ട്രാഫിക്കിന് ടോക്കൺ ഒഴിവാക്കപ്പെടുന്നു. Tailscale ഇല്ലാതെ, `STUDIO_BIND` ഉപയോഗിച്ച് ഒരു സ്വകാര്യ വിലാസത്തിലേക്ക് bind ചെയ്ത് `STUDIO_TOKEN` സജ്ജമാക്കുക. സെർവറുകൾ `projects/.servers/` വഴിയോ Settings-ലെ മാനുവൽ പെയറിങ് വഴിയോ പരസ്പരം കണ്ടെത്തുന്നു.

**ഓട്ടോസ്റ്റാർട്ട്.** macOS: `node scripts/install-studio-macos.mjs` ഒരു LaunchAgent (`net.studio-local.server`) ഇൻസ്റ്റാൾ ചെയ്യുന്നു. Windows: `scripts/start-studio-windows.ps1` ഒരു Task Scheduler ടാസ്കായി രജിസ്റ്റർ ചെയ്യുക (ആക്ഷൻ `conhost.exe --headless powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -File <path>`, ലോഗോണിൽ റൺ ചെയ്യുക, ഇരട്ട ഇൻസ്റ്റൻസുകൾ ഇല്ല, ഓരോ മിനിറ്റിലും വീണ്ടും ശ്രമിക്കുക); അപ്ഗ്രേഡിന് ശേഷം സജീവ റണ്ണുകൾ ഇല്ലാതാകുമ്പോൾ `scripts/restart-studio-windows.ps1` അതിനെ പുനരാരംഭിക്കുന്നു.

**അപ്ഗ്രേഡ് ചെയ്യൽ.** `public/` എന്നതിന് കീഴിലുള്ള ഫ്രണ്ട്-എൻഡ് ഫയലുകൾ ഓരോ അഭ്യർത്ഥനയിലും വായിക്കപ്പെടുന്നു, സിങ്ക് ആയ ഉടൻ പ്രാബല്യത്തിൽ വരുന്നു; `src/` എന്നതിന് കീഴിലുള്ള മാറ്റങ്ങൾക്ക് എല്ലാ മെഷീനിലും റീസ്റ്റാർട്ട് ആവശ്യമാണ്.

```json
}
```

സ്റ്റാറ്റിക് പേജുകളിൽ `command`, `port`, `dataPaths` എന്നിവ ഒഴിവാക്കുന്നു. ഓരോ Artifact-നും സ്വന്തം സ്ഥിരമായ പ്രിവ്യൂ പോർട്ടും origin-ഉം ലഭിക്കുന്നു; പ്രിവ്യൂവിന്റെ `localStorage` പ്രോജക്റ്റിലേക്ക് സംരക്ഷിക്കുകയും സിങ്ക് ചെയ്യുകയും ചെയ്യുന്നു, അതിനാൽ ഒരു മെഷീനിൽ സേവ് ചെയ്ത ഗെയിം മറ്റൊന്നിൽ തുടരാം. ബാക്കെൻഡുകൾ `PORT`, `HOST` എന്നിവയോടെ സാധാരണ ലോക്കൽ പ്രോസസുകളായി (sandbox അല്ല) പ്രവർത്തിക്കുന്നു; **Snapshot** ബാക്കെൻഡ് നിർത്തി പ്രഖ്യാപിച്ച ഡാറ്റ പാതകൾ പകർത്തുന്നു, **Restore** അവ തിരികെ വയ്ക്കുന്നു.

പ്രിവ്യൂവിൽ, *ഒരു എലമെന്റോ ടെക്സ്റ്റോ canvas-ലെ ഒരു ഭാഗമോ തിരഞ്ഞെടുത്ത്* ഒരു കമന്റ് എഴുതുക: അത് നിങ്ങൾ തിരഞ്ഞെടുക്കുന്ന ഏജന്റിനുള്ള ഒരു ടാസ്കായി മാറുന്നു, തിരഞ്ഞെടുത്തത് തെളിവായി ഉൾപ്പെടുന്നു (DOM പാത, ഉദ്ധരിച്ച ടെക്സ്റ്റ് അല്ലെങ്കിൽ canvas-ന്റെ PNG). ഒരു Artifact-ലെ കമന്റുകൾ ക്രമത്തിൽ പ്രവർത്തിക്കുന്നു; വ്യത്യസ്ത Artifacts-ഉം സംഭാഷണങ്ങളും സമാന്തരമായി പ്രവർത്തിക്കുന്നു. `examples/persistent-game/` (Node ബാക്കെൻഡ് + SQLite + Canvas), `examples/artifact-compatibility/` എന്നിവ കാണുക.

## ഫയലുകളും കോൺഫിഗറേഷനും

| സ്ഥാനം | ഉള്ളടക്കം |
| --- | --- |
| `projects/<id>/` | പ്രോജക്റ്റ് വർക്കിങ് ഡയറക്ടറി: കോഡ്, Artifacts, ഡാറ്റ (സിങ്ക് ചെയ്യുന്നു) |
| `projects/<id>/.studio/events/` | ആധികാരികവും മാറ്റമില്ലാത്തതുമായ സംഭാഷണ ജേണൽ |
| `projects/<id>/.studio/state.json`, `history-index.md`, `sessions/`, `artifacts/` | പുനർനിർമ്മിക്കാവുന്ന സ്റ്റേറ്റും ഏജന്റുകൾക്ക് വായിക്കാവുന്ന ചരിത്രവും |
| `projects/<id>/.studio/artifact-storage/`, `snapshots/`, `attachments/` | സിങ്ക് ചെയ്ത പ്രിവ്യൂ സ്റ്റോറേജ്, ഡാറ്റ സ്നാപ്ഷോട്ടുകൾ, കമന്റ് തെളിവുകൾ |
| `projects/<id>/uploads/` | ചാറ്റിലേക്കോ റിസോഴ്സ് പാനലിലേക്കോ ഇടുന്ന ഫയലുകൾ |
| `projects/.servers/` | കണ്ടെത്തലിനായുള്ള സെർവറുകളുടെ പൊതു വിലാസങ്ങൾ (രഹസ്യങ്ങൾ ഇല്ല) |
| `projects/.deleted/<id>.json` | ഡിലീറ്റ് ചെയ്ത പ്രോജക്റ്റുകളുടെ ടൂംസ്റ്റോണുകൾ (സിങ്ക് ചെയ്യുന്നു); വൈകിയ സിങ്ക് വീണ്ടും സൃഷ്ടിക്കുന്ന ഫോൾഡർ വീണ്ടും നീക്കം ചെയ്യപ്പെടുന്നു |

| `~/.studio-local/agent-profiles.json` | ഓപ്ഷണൽ: ഓരോ CLI കുടുംബത്തിനും (`claude`, `codex`) അല്ലെങ്കിൽ ഓരോ അക്കൗണ്ട് id-യ്ക്കും എക്സിക്യൂട്ടബിൾ പാത / env |

ഒരു പ്രോജക്റ്റ് ഡിലീറ്റ് ചെയ്യുന്നത് സ്ഥിരമാണ് (ആർക്കൈവ് ചെയ്യുന്നത് തിരിച്ചെടുക്കാവുന്നതായി തുടരുന്നു), ജോലി ക്യൂവിലോ പ്രവർത്തനത്തിലോ കാത്തിരിപ്പിലോ ആയിരിക്കുമ്പോൾ അത് നിരസിക്കപ്പെടുന്നു. ഡിലീറ്റ് ചെയ്യുന്ന സെർവർ ഒരു ടൂംസ്റ്റോൺ എഴുതുന്നു, തുടർന്ന് `projects/<id>/` ഫോൾഡർ മുഴുവനായി നീക്കം ചെയ്യുന്നു; നിങ്ങളുടെ സിങ്ക് ടൂൾ ഇവ രണ്ടും മറ്റ് മെഷീനുകളിലേക്ക് എത്തിക്കുന്നു. ഓരോ സെർവറും ഒരു പുതിയ ടൂംസ്റ്റോൺ കാണുമ്പോൾ, അതിന്റെ ശേഷിക്കുന്ന പകർപ്പ്, പ്രോജക്റ്റിന്റെ സ്ഥിരമായി പ്രവർത്തിക്കുന്ന ഏജന്റ് പ്രോസസുകൾ, Artifact പ്രിവ്യൂ പോർട്ടുകൾ, കൂടാതെ വർക്കിങ് ഡയറക്ടറി പ്രോജക്റ്റിനുള്ളിലായിരുന്ന Claude ട്രാൻസ്ക്രിപ്റ്റുകൾ (ഓരോ കോൺഫിഗ് ഡയറക്ടറിയിലെയും `projects/<encoded path>*`), Codex rollouts (അവയുടെ ആദ്യ വരിയിലെ `cwd` വഴി പൊരുത്തപ്പെടുത്തുന്നു) എന്നിവ നീക്കം ചെയ്യുന്നു. കൈകാര്യം ചെയ്ത ID-കൾ `~/.studio-local/purged-projects.json`-ൽ രേഖപ്പെടുത്തുന്നു. പഴയ പതിപ്പുകൾ സോഫ്റ്റ്-ഡിലീറ്റ് ചെയ്ത പ്രോജക്റ്റുകൾ (`deletedAt`) സ്റ്റാർട്ടപ്പിൽ ഒരിക്കൽ നീക്കം ചെയ്യപ്പെടുന്നു.

## പതിവ് ചോദ്യങ്ങൾ

**ഇത് എന്റെ API കീ ഉപയോഗിക്കുമോ?** നിങ്ങൾ ഒരു API കീ അക്കൗണ്ട് ചേർത്താൽ മാത്രം. സബ്സ്ക്രിപ്ഷൻ അക്കൗണ്ടുകൾ CLI-കളുടെ സ്വന്തം സൈൻ ഇൻ വഴി പ്രവർത്തിക്കുന്നു; Studiolo സ്വന്തമായി ക്രെഡൻഷ്യലുകൾ ഒന്നും സംഭരിക്കുന്നില്ല.

**എന്റെ ടെർമിനലിലെ `claude` / `codex` ബാധിക്കപ്പെടുമോ?** ഇല്ല. Studiolo അക്കൗണ്ടുകൾ അവയുടെ സ്വന്തം ഡയറക്ടറികളിലാണ്; ക്രമീകരണങ്ങൾ പകർത്താനും skills ലിങ്ക് ചെയ്യാനും മാത്രം `~/.claude`, `~/.codex` എന്നിവ ഒരിക്കൽ വായിക്കുന്നു.

**ഇതൊരു sandbox ആണോ?** അല്ല. ഏജന്റുകളും Artifact ബാക്കെൻഡുകളും നിങ്ങളുടെ അനുമതികളോടെ പ്രവർത്തിക്കുന്ന നിങ്ങളുടെ സ്വന്തം ലോക്കൽ പ്രോസസുകളാണ്, ടെർമിനലിലെ CLI-കളെപ്പോലെ തന്നെ.

**എന്റെ ഫോണിൽ നിന്ന് ഉപയോഗിക്കാമോ?** ഉവ്വ്, Tailscale വഴി ഒരു ബ്രൗസർ ക്ലയന്റായി; CLI-കൾ നിങ്ങളുടെ കമ്പ്യൂട്ടറുകളിലാണ് പ്രവർത്തിക്കുന്നത്.

**എന്തുകൊണ്ട് ഡിപൻഡൻസികൾ ഇല്ല?** സെർവർ ശുദ്ധമായ Node.js ആണ് (ESM, `node:` മൊഡ്യൂളുകൾ മാത്രം); അതിനാൽ Node 22 പ്രവർത്തിക്കുന്ന എവിടെയും ഇത് പ്രവർത്തിക്കും, സപ്ലൈ ചെയിനിലെ ഒന്നും നിങ്ങൾക്കും നിങ്ങളുടെ CLI-കൾക്കും ഇടയിൽ വരുന്നില്ല.
