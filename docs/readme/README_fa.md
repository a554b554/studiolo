## نصب با یک عامل برنامه‌نویسی

این متن را در Claude Code، Codex یا هر عامل برنامه‌نویسی که بتواند روی دستگاه موردنظرتان فرمان اجرا کند بچسبانید:

```text
Studiolo را از https://github.com/a554b554/studiolo نصب کن: مخزن را clone کن، مطمئن شو Node.js نسخه 22.14 یا بالاتر در دسترس است و CLIهای `claude` و/یا `codex` نصب شده‌اند، `node src/server.mjs` را از ریشه مخزن اجرا کن، بررسی کن که http://127.0.0.1:4310 پاسخ می‌دهد، سپس به من بگو Settings → Hosts & accounts را باز کنم تا وارد حساب‌هایم شوم. خودت وارد هیچ حسابی نشو.
```

یا به‌صورت دستی:

```sh
git clone https://github.com/a554b554/studiolo studiolo && cd studiolo
node src/server.mjs        # http://127.0.0.1:4310
```

Studiolo هیچ وابستگی npm ندارد؛ نیازی به `npm install` نیست. آزمون‌ها: `node --test test/*.test.mjs`.

## Studiolo چیست

Studiolo یک میز کار وب خودمیزبان است که CLIهای **Claude Code** و **Codex** را که از قبل روی رایانه‌هایتان نصب شده‌اند به کار می‌گیرد. این فقط یک رابط گفتگوی دیگر روی یک کلید API نیست:

- **اشتراک‌های شما، CLIهای شما.** هر درخواست از طریق فرایند واقعی `claude` یا `codex` اجرا می‌شود؛ با همان ابزارها، مهارت‌ها، سرورهای MCP، حالت‌های مجوز و رفتار عامل که در ترمینال دارید. ورود با اشتراک یا با کلید API؛ انتخاب برای هر حساب با شماست.
- **حساب‌ها برای هر دستگاه، با مدیریت Studiolo.** روی هر رایانه از طریق مرورگر وارد چندین حساب Claude و Codex شوید. هر حساب پوشه پیکربندی CLI ایزوله خودش را دارد؛ به `~/.claude` یا `~/.codex` شخصی شما دست زده نمی‌شود. سهمیه هر حساب به‌صورت زنده نمایش داده می‌شود.
- **یک تاریخچه پروژه در همه دستگاه‌ها.** پروژه‌ها در پوشه‌ای قرار دارند که آن را به هر روشی که دوست دارید همگام می‌کنید (مثلاً Syncthing). تاریخچه گفتگوها یک دفتر رویداد فقط‌افزودنی است که به‌صورت قطعی ادغام می‌شود؛ هر دستگاه همان سرور را اجرا می‌کند و همان تاریخچه را ارائه می‌دهد. هر گفتگو روی دستگاهی اجرا می‌شود که برایش انتخاب کرده‌اید؛ می‌توانید آن را از هر دستگاهی بخوانید و ادامه دهید.
- **تجربه ترمینال، در مرورگر.** یک نوبت را با Esc متوقف کنید، عامل در حال کار را با یک پیام تکمیلی هدایت کنید، `/` را برای فرمان‌های اسلش خود CLI تایپ کنید؛ همه به پروتکل‌های بومی نگاشت شده‌اند، نه اینکه دوباره پیاده‌سازی شده باشند.
- **Artifacts و نظرات درون صفحه.** برنامه‌های وبی که عامل‌ها می‌سازند به‌صورت Artifact با بک‌اند ماندگار و ذخیره‌سازی همگام اجرا می‌شوند؛ چیزی را در پیش‌نمایش انتخاب کنید و آن را به‌عنوان یک کار برای عامل بفرستید.

## شروع سریع

1. **پیش‌نیازها**: Node.js نسخه 22.14 یا بالاتر، و CLI `claude` و/یا `codex` نصب‌شده روی دستگاه (`claude --version`، `codex --version`).
2. **اجرا کنید** `node src/server.mjs` و <http://127.0.0.1:4310> را باز کنید.
3. **افزودن حساب‌ها**: Settings → *Hosts & accounts* → *Add account*. دستگاه، نوع (Claude Code / Codex) و روش ورود را انتخاب کنید، سپس مراحل نمایش داده‌شده را دنبال کنید (پایین‌تر را ببینید).
4. **یک پروژه بسازید و گفتگو را آغاز کنید**: کادر نوشتن به ترتیب **دستگاه → حساب → مدل → سطح تلاش → حالت مجوز** را انتخاب می‌کند. نخستین پیام، دستگاه و حساب آن گفتگو را ثابت می‌کند؛ مدل، سطح تلاش و مجوزها را می‌توان در هر پیام تغییر داد. مدل تازه همان نشست بومی را ادامه می‌دهد و نخستین نوبت آن، زمینه را بدون حافظهٔ نهان پرامپت دوباره می‌خواند.

متغیرهای محیطی: `STUDIO_STATE_DIR` (وضعیت خصوصی دستگاه، پیش‌فرض `~/.studio-local`)، `STUDIO_BIND`، `STUDIO_PORT` (4310)، `STUDIO_PREVIEW_PORT` (4311)، `STUDIO_TOKEN`، `STUDIO_UPLOAD_LIMIT` (بر حسب بایت، پیش‌فرض 100 MB). برای هر پوشه وضعیت یک سرور.

## حساب کاربری و ورود

حساب‌ها به یک دستگاه تعلق دارند و از مرورگر ساخته می‌شوند. هر حساب پوشه‌ای زیر `~/.studio-local/accounts/<id>/` است که به‌عنوان `CLAUDE_CONFIG_DIR` یا `CODEX_HOME` به کار می‌رود؛ بنابراین چند حساب از یک CLI کنار هم وجود دارند و ورود خود ترمینال شما هرگز تغییر نمی‌کند. هنگام ساخت حساب، Studiolo آن پوشه را از پوشه پیش‌فرض CLI شما مقداردهی می‌کند: `settings.json` / `CLAUDE.md` (در Codex: `config.toml` / `AGENTS.md`) را کپی می‌کند و برای `skills`، `plugins` و موارد مشابه پیوند می‌سازد؛ بنابراین عامل‌ها مهارت‌ها و سرورهای MCP که از قبل استفاده می‌کنید را حفظ می‌کنند. اطلاعات ورود هرگز کپی نمی‌شوند.

| نوع | روش | چه اتفاقی می‌افتد |
| --- | --- | --- |
| Claude Code | **اشتراک** | Studiolo فرمان `claude auth login` را اجرا می‌کند؛ پیوند را باز می‌کنید، وارد می‌شوید و کد مجوز را در صفحه می‌چسبانید. |
| Claude Code | **کلید Anthropic API** | کلید در پوشه حساب ذخیره می‌شود (با حالت 0600) و به‌عنوان `ANTHROPIC_API_KEY` ارسال می‌شود؛ از طریق دست‌دهی CLI تأیید می‌شود و اگر رد شود حذف می‌گردد. پرداخت به‌ازای مصرف، بدون پنجره‌های سهمیه. |
| Codex | **ChatGPT** | کد دستگاه از طریق app-server در Codex: صفحه یک پیوند و یک کد یک‌بارمصرف نشان می‌دهد؛ از هر مرورگری وارد شوید، صفحه پس از پایان به‌روز می‌شود. |
| Codex | **کلید OpenAI API** | خود Codex آن را در `CODEX_HOME` حساب ذخیره می‌کند. |

پس از ورود، Studiolo هویت حساب (ایمیل، طرح) و فهرست مدل‌ها را مستقیماً از CLI می‌خواند، بدون مصرف هیچ درخواست مدلی، و برای Claude فرمان‌های اسلش CLI را هم برای تکمیل خودکار کادر نوشتن می‌خواند. حسابی که نام سفارشی ندارد به نام ایمیلش تغییر نام می‌یابد، تا کادر نوشتن، سربرگ گفتگو، هر پاسخ و پنل مصرف نشان دهند چه کسی صحبت می‌کند. حساب‌ها را می‌توان تغییر نام داد، تازه‌سازی کرد، از آن‌ها خارج شد (`claude auth logout` / `codex logout`) یا حذفشان کرد؛ گفتگویی که حسابش حذف شده می‌تواند با حساب دیگری روی همان دستگاه ادامه یابد.

پنل مصرف (پایین سمت چپ) دستگاه انتخاب‌شده در کادر نوشتن را دنبال می‌کند: اشتراک‌های Claude پنجره ۵ ساعته را نشان می‌دهند، Codex پنجره هفتگی را، و حساب‌های کلید API بر اساس مصرف صورت‌حساب می‌شوند. این پنل نقاط پایانی مصرف خود CLIها (`get_usage`، `account/rateLimits/read`) را می‌خواند، به مدت 60 ثانیه کش می‌کند، هرگز سرکشی دوره‌ای نمی‌کند و هرگز برای حسابی که از آن خارج شده‌اید CLI را اجرا نمی‌کند.

همه این‌ها برای دستگاه‌های راه دور هم کار می‌کند: میزبان آنلاین دیگری را در *Hosts & accounts* انتخاب کنید تا درخواست‌ها به آن بازارسال شوند.

## گفتگو مانند CLI

هر گفتگو یک فرایند بومی مقیم دارد، Claude Code از طریق `stream-json` دوطرفه و Codex از طریق `app-server`، بنابراین عامل دقیقاً مانند ترمینال رفتار می‌کند. کنترل‌های وب به پروتکل‌های بومی نگاشت می‌شوند:

| در ترمینال | در Studiolo | چگونه |
| --- | --- | --- |
| Esc برای توقف | **■ Stop** یا Esc در کادر نوشتن | درخواست کنترلی `interrupt` در Claude / `turn/interrupt` در Codex. فرایند و نشست بومی باقی می‌مانند؛ پاسخ ناتمام نگه داشته می‌شود؛ پیام‌های بعدی همان نشست را ادامه می‌دهند. |
| تایپ کردن در حین کار عامل | ارسال در حین اجرای یک نوبت = **Steer** | Claude آن را در مرز ابزار بعدی می‌خواند؛ در Codex `turn/steer`. به‌صورت *You · steer* نمایش داده می‌شود؛ پاسخ در یک بخش جدید ادامه می‌یابد. **Queue** در عوض پیام را پس از پایان نوبت می‌فرستد. |
| `/compact`، `/context`، فرمان‌های سفارشی، مهارت‌ها | `/` را تایپ کنید تا فهرست فرمان‌ها ظاهر شود | فرمان‌های Claude بی‌کم‌وکاست عبور می‌کنند (فهرست از خود CLI می‌آید). Codex فرمان متنی ندارد؛ `/compact`، `/review`، `/skills`، `/mcp` به درخواست‌های app-server نگاشت می‌شوند. |
| — | `/model`، `/effort`، `/mode`، `/rename`، `/new`، `/status`، `/clear`، `/stop`، `/help` | فرمان‌های پلتفرم که در مرورگر یا توسط صف پردازش می‌شوند. |

درخواست‌های مجوزی که CLI در ترمینال می‌پرسید در صفحه ظاهر می‌شوند: یک بار تأیید یا رد کنید و همان اجرا ادامه می‌یابد. حالت خودکار همان حالت خود CLI است (`auto` در Claude، `auto_review` در Codex)؛ Studiolo هرگز پرچم‌های دور زدن یا قوانین مجوز دائمی اضافه نمی‌کند. سطح تلاش استدلال و مدل را می‌توان در هر پیام درون یک گفتگو تغییر داد (`set_model` / `apply_flag_settings` در Claude، پارامترهای `turn/start` در Codex).

در حین اجرای یک نوبت، گفتگو کار را همان‌طور که CLIها نشان می‌دهند نمایش می‌دهد: آنچه agent بین گام‌ها می‌گوید کامل باقی می‌ماند، فراخوانی‌های پیاپی ابزار در یک خطِ بازشدنی جمع می‌شوند، و گام در حال اجرا و زمان سپری‌شده همیشه دیده می‌شوند؛ وقتی پاسخ می‌رسد، کل اجرا در raw log خودش جمع می‌شود. پیامی که می‌فرستید بی‌درنگ نمایش داده می‌شود و در پس‌زمینه تحویل می‌گردد (در صورت شکست می‌توان دوباره تلاش کرد). در نوار کناری، نشانگری چرخان گفتگوها و پروژه‌هایی را که در حال کارند و یک نقطه نتایجی را که هنوز ندیده‌اید مشخص می‌کند.

## کار با چند دستگاه

همان سرور را روی همه رایانه‌ها اجرا کنید؛ `projects/` را در پوشه‌ای بگذارید که همگام می‌کنید (Syncthing یا هر ابزار همگام‌سازی فایل). `.studio/events/` هر پروژه یک دفتر رویداد تغییرناپذیر با ترتیب علّی است؛ دستگاه‌های آنلاین دفترها را مستقیماً هم مبادله می‌کنند تا تغییرات در چند ثانیه ظاهر شوند. هر دستگاهی می‌تواند همه گفتگوها را نشان دهد؛ اجرا همیشه روی دستگاهی انجام می‌شود که گفتگو به آن متصل است، و نشست‌های بومی CLI هرگز جابه‌جا نمی‌شوند.

**دسترسی به دستگاه‌های دیگر.** ساده‌ترین پیکربندی امن [Tailscale](https://tailscale.com) است: `tailnet.json` (`{"enabled":true,"command":"tailscale"}`) و یک `access-token.txt` تصادفی (دست‌کم 32 نویسه) را در پوشه وضعیت بگذارید، سرور را عادی اجرا کنید تا Studiolo درگاهش را با `tailscale serve` منتشر کند؛ `http://<machine>:4310` را باز کنید و توکن را یک بار وارد کنید. با `"trustTailnet":true` توکن برای ترافیک tailnet نادیده گرفته می‌شود. بدون Tailscale، با `STUDIO_BIND` به یک نشانی خصوصی متصل شوید و `STUDIO_TOKEN` را تنظیم کنید. سرورها یکدیگر را از طریق `projects/.servers/` یا با جفت‌سازی دستی در Settings پیدا می‌کنند.

**اجرای خودکار.** در macOS: `node scripts/install-studio-macos.mjs` یک LaunchAgent (`net.studio-local.server`) نصب می‌کند. در Windows: `scripts/start-studio-windows.ps1` را به‌عنوان یک کار در Task Scheduler ثبت کنید (کنش `conhost.exe --headless powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -File <path>`، اجرا هنگام ورود به سیستم، بدون نمونه‌های تکراری، تلاش دوباره هر دقیقه)؛ `scripts/restart-studio-windows.ps1` پس از ارتقا، هنگامی که اجرای فعالی وجود نداشته باشد، آن را دوباره راه‌اندازی می‌کند.

**ارتقا.** فایل‌های فرانت‌اند زیر `public/` در هر درخواست خوانده می‌شوند و بلافاصله پس از همگام‌سازی اعمال می‌شوند؛ تغییرات زیر `src/` به راه‌اندازی دوباره روی همه دستگاه‌ها نیاز دارند.

## Artifact و نظرات درون صفحه

از یک عامل یک صفحه وب یا برنامه بخواهید تا فایل `studio.artifacts.json` را در ریشه پروژه نگهداری کند:

```json
{
  "artifacts": [
    { "key": "game", "name": "Click the target", "root": "game", "entry": "index.html",
      "command": ["node", "server.mjs"], "port": 4320, "dataPaths": ["game/data"] }
  ]
}
```

صفحه‌های ایستا `command`، `port` و `dataPaths` را حذف می‌کنند. هر Artifact درگاه و origin پیش‌نمایش ماندگار خودش را دارد؛ `localStorage` پیش‌نمایش در پروژه ذخیره و همگام می‌شود، بنابراین بازی‌ای که روی یک دستگاه ذخیره شده روی دستگاه دیگر ادامه می‌یابد. بک‌اندها به‌صورت فرایندهای محلی معمولی (نه یک sandbox) با `PORT` و `HOST` اجرا می‌شوند؛ **Snapshot** بک‌اند را متوقف و مسیرهای داده اعلام‌شده را کپی می‌کند، **Restore** آن‌ها را بازمی‌گرداند.

در پیش‌نمایش، *یک عنصر، متن یا ناحیه‌ای از canvas را انتخاب کنید* و نظری بنویسید: این نظر به کاری برای عامل انتخابی شما تبدیل می‌شود و انتخاب به‌عنوان شاهد همراه آن است (مسیر DOM، متن نقل‌شده یا یک PNG از canvas). نظرها روی یک Artifact به ترتیب اجرا می‌شوند؛ Artifactهای مختلف و گفتگوهای مختلف به‌صورت موازی اجرا می‌شوند. `examples/persistent-game/` (بک‌اند Node + SQLite + Canvas) و `examples/artifact-compatibility/` را ببینید.

| مکان | محتوا |
| --- | --- |
| `projects/<id>/` | پوشه کاری پروژه: کد، Artifacts، داده‌ها (همگام‌شده) |
| `projects/<id>/.studio/events/` | دفتر رویداد مرجع و تغییرناپذیر گفتگوها |
| `projects/<id>/.studio/state.json`، `history-index.md`، `sessions/`، `artifacts/` | وضعیت قابل بازسازی و تاریخچه خوانا برای عامل‌ها |
| `projects/<id>/.studio/artifact-storage/`، `snapshots/`، `attachments/` | ذخیره‌سازی همگام پیش‌نمایش، اسنپ‌شات‌های داده، شواهد نظرها |
| `projects/<id>/uploads/` | فایل‌هایی که در گفتگو یا پنل منابع رها می‌شوند |
| `projects/.servers/` | نشانی‌های عمومی سرورها برای کشف (بدون اطلاعات محرمانه) |
| `projects/.deleted/<id>.json` | نشانه‌های پروژه‌های حذف‌شده (همگام‌شده)؛ پوشه‌ای که همگام‌سازی دیرهنگام دوباره بسازد، دوباره حذف می‌شود |
| `~/.studio-local/` | خصوصی دستگاه: هویت، `accounts.json`، `accounts/<id>/`، جفت‌سازی، تنظیمات Tailscale؛ هرگز همگام نکنید |
| `~/.studio-local/agent-profiles.json` | اختیاری: مسیر فایل اجرایی / متغیرهای محیطی برای هر خانواده CLI (`claude`، `codex`) یا برای هر شناسه حساب |

حذف پروژه دائمی است (بایگانی برگشت‌پذیر می‌ماند) و تا زمانی که کاری در صف، در حال اجرا یا در انتظار باشد رد می‌شود. سروری که حذف را انجام می‌دهد یک نشانه حذف می‌نویسد و سپس کل پوشه `projects/<id>/` را پاک می‌کند؛ ابزار همگام‌سازی شما هر دو را به دستگاه‌های دیگر می‌برد. هر سرور با دیدن یک نشانه حذف جدید، نسخه باقی‌مانده خود، فرایندهای عامل مقیم پروژه و درگاه‌های پیش‌نمایش Artifact را حذف می‌کند، و همچنین رونوشت‌های Claude (`projects/<encoded path>*` در هر پوشه پیکربندی) و rolloutهای Codex (که با `cwd` در خط اولشان تطبیق داده می‌شوند) را که پوشه کاری‌شان درون پروژه بوده است. شناسه‌های پردازش‌شده در `~/.studio-local/purged-projects.json` ثبت می‌شوند. پروژه‌هایی که نسخه‌های قدیمی‌تر به‌صورت نرم حذف کرده‌اند (`deletedAt`) یک بار هنگام راه‌اندازی حذف می‌شوند.

## سوالات متداول

**آیا از کلید API من استفاده می‌کند؟** فقط اگر یک حساب با کلید API اضافه کنید. حساب‌های اشتراکی از طریق ورود خود CLIها اجرا می‌شوند؛ Studiolo هیچ اطلاعات ورودی از خودش ذخیره نمی‌کند.

**آیا `claude` / `codex` ترمینال من تحت تأثیر قرار می‌گیرد؟** خیر. حساب‌های Studiolo در پوشه‌های خودشان قرار دارند؛ `~/.claude` و `~/.codex` فقط یک بار برای کپی تنظیمات و پیوند دادن مهارت‌ها خوانده می‌شوند.

**آیا این یک sandbox است؟** خیر. عامل‌ها و بک‌اندهای Artifact فرایندهای محلی خود شما با مجوزهای شما هستند، دقیقاً مانند CLIها در ترمینال.

**آیا می‌توانم از تلفنم استفاده کنم؟** بله، به‌عنوان یک کلاینت مرورگر از طریق Tailscale؛ CLIها روی رایانه‌های شما اجرا می‌شوند.

**چرا بدون هیچ وابستگی؟** سرور با Node.js خالص نوشته شده است (ESM، فقط ماژول‌های `node:`)، بنابراین هر جا که Node 22 اجرا شود اجرا می‌شود و هیچ چیزی از زنجیره تأمین میان شما و CLIهایتان قرار نمی‌گیرد.
