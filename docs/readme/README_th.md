## ติดตั้งด้วย coding agent

วางข้อความนี้ลงใน Claude Code, Codex หรือ coding agent ใดก็ได้ที่รันคำสั่งบนเครื่องที่คุณต้องการใช้งานได้:

```text
ติดตั้ง Studiolo จาก https://github.com/a554b554/studiolo: clone repository ตรวจสอบให้แน่ใจว่ามี Node.js 22.14+ และติดตั้ง CLI `claude` และ/หรือ `codex` แล้ว รัน `node src/server.mjs` จากรากของ repository ยืนยันว่า http://127.0.0.1:4310 ตอบสนอง จากนั้นบอกให้ฉันเปิด Settings → Hosts & accounts เพื่อลงชื่อเข้าใช้บัญชีของฉัน ห้ามลงชื่อเข้าใช้บัญชีใดด้วยตัวเอง
```

หรือทำด้วยมือ:

```sh
git clone https://github.com/a554b554/studiolo studiolo && cd studiolo
node src/server.mjs        # http://127.0.0.1:4310
```

Studiolo ไม่มี dependency ของ npm จึงไม่จำเป็นต้องรัน `npm install` การทดสอบ: `node --test test/*.test.mjs`

## Studiolo คืออะไร

Studiolo คือโต๊ะทำงานบนเว็บแบบ self-hosted ที่ควบคุม CLI ของ **Claude Code** และ **Codex** ซึ่งติดตั้งอยู่บนคอมพิวเตอร์ของคุณแล้ว มันไม่ใช่ UI แชตอีกตัวที่ครอบ API key ไว้:

- **การสมัครสมาชิกของคุณ CLI ของคุณ** ทุกคำขอทำงานผ่านโปรเซส `claude` หรือ `codex` ตัวจริง — เครื่องมือ skill เซิร์ฟเวอร์ MCP โหมดสิทธิ์ และพฤติกรรมของ agent เหมือนกับในเทอร์มินัลทุกประการ จะลงชื่อเข้าใช้ด้วยการสมัครสมาชิกหรือ API key ก็เลือกได้ตามแต่ละบัญชี
- **บัญชีแยกตามเครื่อง จัดการโดย Studiolo** ลงชื่อเข้าใช้บัญชี Claude และ Codex หลายบัญชีบนคอมพิวเตอร์แต่ละเครื่องได้จากเบราว์เซอร์ แต่ละบัญชีมีไดเรกทอรีการกำหนดค่า CLI ที่แยกจากกัน ไม่มีอะไรไปแตะ `~/.claude` หรือ `~/.codex` ส่วนตัวของคุณ โควตาของทุกบัญชีแสดงแบบเรียลไทม์
- **ประวัติโปรเจกต์เดียวกันข้ามเครื่อง** โปรเจกต์อยู่ในโฟลเดอร์ที่คุณซิงก์ด้วยวิธีใดก็ได้ (เช่น Syncthing) ประวัติบทสนทนาเป็นบันทึกแบบเขียนต่อท้ายอย่างเดียวที่รวมกันได้อย่างกำหนดแน่นอน ทุกเครื่องรันเซิร์ฟเวอร์ตัวเดียวกันและให้บริการประวัติเดียวกัน บทสนทนาจะทำงานบนเครื่องที่คุณเลือกไว้ให้มัน และคุณอ่านหรือทำต่อได้จากเครื่องใดก็ได้
- **ประสบการณ์แบบเทอร์มินัลในเบราว์เซอร์** หยุดเทิร์นด้วย Esc ชี้นำ agent ที่กำลังทำงานด้วยข้อความต่อเนื่อง พิมพ์ `/` เพื่อใช้ slash command ของ CLI เอง — ทั้งหมดแมปเข้ากับโปรโตคอลดั้งเดิม ไม่ได้เขียนขึ้นใหม่
- **Artifact และความคิดเห็นในหน้า** เว็บแอปที่ agent สร้างจะรันเป็น Artifact พร้อม backend ถาวรและพื้นที่จัดเก็บที่ซิงก์กัน เลือกบางอย่างในพรีวิวแล้วส่งให้ agent เป็นงานได้

## เริ่มต้นอย่างรวดเร็ว

1. **สิ่งที่ต้องมี** — Node.js 22.14+ และติดตั้ง CLI `claude` และ/หรือ `codex` บนเครื่อง (`claude --version`, `codex --version`)
2. **รัน** `node src/server.mjs` แล้วเปิด <http://127.0.0.1:4310>
3. **เพิ่มบัญชี** — Settings → *Hosts & accounts* → *Add account* เลือกเครื่อง ประเภท (Claude Code / Codex) และวิธีลงชื่อเข้าใช้ จากนั้นทำตามขั้นตอนที่แสดง (ดูด้านล่าง)
4. **สร้างโปรเจกต์ เริ่มบทสนทนา** — ช่องเขียนข้อความจะเลือก **เครื่อง → บัญชี → โมเดล → effort → โหมดสิทธิ์** ข้อความแรกจะกำหนดเครื่อง บัญชี และโมเดลของบทสนทนานั้นตายตัว ส่วน effort และสิทธิ์เปลี่ยนได้ทุกข้อความ

ตัวแปรสภาพแวดล้อม: `STUDIO_STATE_DIR` (สถานะส่วนตัวของเครื่อง ค่าเริ่มต้น `~/.studio-local`), `STUDIO_BIND`, `STUDIO_PORT` (4310), `STUDIO_PREVIEW_PORT` (4311), `STUDIO_TOKEN`, `STUDIO_UPLOAD_LIMIT` (ไบต์ ค่าเริ่มต้น 100 MB) หนึ่งเซิร์ฟเวอร์ต่อหนึ่งไดเรกทอรีสถานะ

## บัญชีและการลงชื่อเข้าใช้

บัญชีเป็นของเครื่องใดเครื่องหนึ่งและสร้างจากเบราว์เซอร์ แต่ละบัญชีคือไดเรกทอรีภายใต้ `~/.studio-local/accounts/<id>/` ซึ่งใช้เป็น `CLAUDE_CONFIG_DIR` หรือ `CODEX_HOME` ทำให้หลายบัญชีของ CLI เดียวกันอยู่ร่วมกันได้ และการลงชื่อเข้าใช้ของเทอร์มินัลคุณจะไม่ถูกแตะต้องเลย เมื่อสร้างบัญชี Studiolo จะเตรียมไดเรกทอรีนั้นจากไดเรกทอรี CLI เริ่มต้นของคุณ — คัดลอก `settings.json` / `CLAUDE.md` (Codex: `config.toml` / `AGENTS.md`) และลิงก์ `skills`, `plugins` และรายการอื่นทำนองเดียวกัน — เพื่อให้ agent ยังคงมี skill และเซิร์ฟเวอร์ MCP ที่คุณใช้อยู่ ข้อมูลรับรองจะไม่ถูกคัดลอกเด็ดขาด

| ประเภท | วิธี | สิ่งที่เกิดขึ้น |
| --- | --- | --- |
| Claude Code | **การสมัครสมาชิก** | Studiolo รัน `claude auth login` คุณเปิดลิงก์ ลงชื่อเข้าใช้ แล้ววางรหัสอนุญาตกลับลงในหน้า |
| Claude Code | **Anthropic API key** | คีย์ถูกเก็บในไดเรกทอรีของบัญชี (mode 0600) และส่งเป็น `ANTHROPIC_API_KEY` ตรวจสอบผ่าน handshake ของ CLI และถูกทิ้งหากถูกปฏิเสธ จ่ายตามการใช้งาน ไม่มีหน้าต่างโควตา |
| Codex | **ChatGPT** | รหัสอุปกรณ์ผ่าน Codex app-server: หน้าจะแสดงลิงก์และรหัสแบบใช้ครั้งเดียว ลงชื่อเข้าใช้จากเบราว์เซอร์ใดก็ได้ หน้าจะอัปเดตเมื่อเสร็จ |
| Codex | **OpenAI API key** | Codex เป็นผู้จัดเก็บเองใน `CODEX_HOME` ของบัญชี |

หลังลงชื่อเข้าใช้ Studiolo จะอ่านตัวตนของบัญชี (อีเมล แพ็กเกจ) และรายการโมเดลจาก CLI โดยตรง — ไม่ใช้คำขอโมเดลแม้แต่ครั้งเดียว — และสำหรับ Claude จะอ่าน slash command ของ CLI เพื่อใช้เติมคำอัตโนมัติในช่องเขียนข้อความด้วย บัญชีที่ไม่มีชื่อกำหนดเองจะถูกเปลี่ยนชื่อเป็นอีเมลของมัน ช่องเขียนข้อความ หัวบทสนทนา ทุกคำตอบ และแผงการใช้งานจึงบอกได้ว่าใครกำลังพูด บัญชีสามารถเปลี่ยนชื่อ รีเฟรช ลงชื่อออก (`claude auth logout` / `codex logout`) หรือลบได้ บทสนทนาที่บัญชีถูกลบไปแล้วสามารถทำต่อด้วยบัญชีอื่นบนเครื่องเดียวกันได้

แผงการใช้งาน (ล่างซ้าย) จะเปลี่ยนตามเครื่องที่เลือกในช่องเขียนข้อความ: การสมัครสมาชิก Claude แสดงหน้าต่าง 5 ชั่วโมง Codex แสดงหน้าต่างรายสัปดาห์ บัญชี API key คิดเงินตามการใช้งาน แผงนี้อ่าน endpoint การใช้งานของ CLI เอง (`get_usage`, `account/rateLimits/read`) แคชไว้ 60 วินาที ไม่ poll และไม่เคยเริ่ม CLI สำหรับบัญชีที่ลงชื่อออกแล้ว

ทั้งหมดนี้ใช้ได้กับเครื่องระยะไกลด้วย: เลือกโฮสต์อื่นที่ออนไลน์อยู่ใน *Hosts & accounts* แล้วคำขอจะถูกส่งต่อไปยังเครื่องนั้น

## แชตแบบ CLI

แต่ละบทสนทนามีโปรเซสดั้งเดิมที่ทำงานค้างอยู่ของตัวเอง — Claude Code ผ่าน `stream-json` แบบสองทิศทาง, Codex ผ่าน `app-server` — agent จึงทำงานเหมือนในเทอร์มินัลทุกประการ ตัวควบคุมบนเว็บแมปเข้ากับโปรโตคอลดั้งเดิมดังนี้:

| ในเทอร์มินัล | ใน Studiolo | วิธีการ |
| --- | --- | --- |
| Esc เพื่อหยุด | **■ Stop** หรือ Esc ในช่องเขียนข้อความ | คำขอควบคุม `interrupt` ของ Claude / `turn/interrupt` ของ Codex โปรเซสและเซสชันดั้งเดิมยังคงอยู่ คำตอบที่ได้บางส่วนถูกเก็บไว้ ข้อความถัดไปทำต่อในเซสชันเดิม |
| พิมพ์ระหว่างที่ agent ทำงาน | ส่งขณะเทิร์นกำลังทำงาน = **Steer** | Claude อ่านข้อความที่ขอบเขตของเครื่องมือถัดไป ส่วน Codex ใช้ `turn/steer` แสดงเป็น *You · steer* และคำตอบจะต่อในส่วนใหม่ ส่วน **Queue** จะส่งหลังจบเทิร์นแทน |
| `/compact`, `/context`, คำสั่งกำหนดเอง, skill | พิมพ์ `/` เพื่อดูรายการคำสั่ง | คำสั่งของ Claude ถูกส่งผ่านตามตัวอักษร (รายการมาจาก CLI เอง) Codex ไม่มีคำสั่งแบบข้อความ `/compact`, `/review`, `/skills`, `/mcp` จึงถูกแมปเป็นคำขอ app-server |
| — | `/model`, `/effort`, `/mode`, `/rename`, `/new`, `/status`, `/clear`, `/stop`, `/help` | คำสั่งของแพลตฟอร์มที่จัดการในเบราว์เซอร์หรือโดยคิว |

คำขอสิทธิ์ที่ CLI จะถามในเทอร์มินัลจะปรากฏในหน้าเว็บ: อนุมัติครั้งเดียวหรือปฏิเสธ แล้วการทำงานเดิมจะดำเนินต่อ โหมดอัตโนมัติเป็นโหมดของ CLI เอง (Claude `auto`, Codex `auto_review`) Studiolo ไม่เคยเพิ่มแฟล็กข้ามสิทธิ์หรือกฎอนุญาตถาวร effort ในการให้เหตุผลและโมเดลเปลี่ยนได้ทุกข้อความภายในบทสนทนา (Claude `set_model` / `apply_flag_settings`, พารามิเตอร์ `turn/start` ของ Codex)

## หลายเครื่อง

รันเซิร์ฟเวอร์ตัวเดียวกันบนคอมพิวเตอร์ทุกเครื่อง แล้ววาง `projects/` ไว้ในโฟลเดอร์ที่คุณซิงก์ (Syncthing หรือเครื่องมือซิงก์ไฟล์ใดก็ได้) `.studio/events/` ของแต่ละโปรเจกต์เป็นบันทึกที่เปลี่ยนแปลงไม่ได้และเรียงลำดับตามเหตุและผล เครื่องที่ออนไลน์อยู่ยังแลกเปลี่ยนบันทึกกันโดยตรงด้วย การเปลี่ยนแปลงจึงปรากฏภายในไม่กี่วินาที เครื่องใดก็แสดงบทสนทนาได้ทุกบทสนทนา แต่การทำงานจะเกิดบนเครื่องที่บทสนทนาผูกไว้เสมอ และเซสชัน CLI ดั้งเดิมไม่เคยย้ายเครื่อง

**การเข้าถึงเครื่องอื่น** การตั้งค่าที่ปลอดภัยและง่ายที่สุดคือ [Tailscale](https://tailscale.com): วาง `tailnet.json` (`{"enabled":true,"command":"tailscale"}`) และ `access-token.txt` แบบสุ่ม (≥ 32 อักขระ) ไว้ในไดเรกทอรีสถานะ เริ่มตามปกติ แล้ว Studiolo จะเผยแพร่พอร์ตของมันด้วย `tailscale serve` เปิด `http://<machine>:4310` แล้วกรอกโทเค็นครั้งเดียว เมื่อตั้ง `"trustTailnet":true` จะข้ามโทเค็นสำหรับทราฟฟิกใน tailnet หากไม่ใช้ Tailscale ให้ bind กับแอดเดรสส่วนตัวด้วย `STUDIO_BIND` และตั้ง `STUDIO_TOKEN` เซิร์ฟเวอร์ค้นพบกันผ่าน `projects/.servers/` หรือด้วยการจับคู่ด้วยตนเองใน Settings

**เริ่มอัตโนมัติ** macOS: `node scripts/install-studio-macos.mjs` จะติดตั้ง LaunchAgent (`net.studio-local.server`) Windows: ลงทะเบียน `scripts/start-studio-windows.ps1` เป็นงานของ Task Scheduler (action `conhost.exe --headless powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -File <path>` รันเมื่อล็อกออน ไม่รันซ้ำซ้อน ลองใหม่ทุกนาที) `scripts/restart-studio-windows.ps1` จะรีสตาร์ตหลังอัปเกรดเมื่อไม่มีงานที่กำลังรันอยู่

**การอัปเกรด** ไฟล์ front-end ใน `public/` ถูกอ่านทุกคำขอและมีผลทันทีที่ซิงก์ ส่วนการเปลี่ยนแปลงใน `src/` ต้องรีสตาร์ตบนทุกเครื่อง

## Artifact และความคิดเห็นในหน้า

ขอให้ agent สร้างหน้าเว็บหรือแอป แล้วมันจะดูแล `studio.artifacts.json` ที่รากของโปรเจกต์:

```json
{
  "artifacts": [
    { "key": "game", "name": "Click the target", "root": "game", "entry": "index.html",
      "command": ["node", "server.mjs"], "port": 4320, "dataPaths": ["game/data"] }
  ]
}
```

หน้าเว็บแบบสแตติกจะไม่ใส่ `command`, `port` และ `dataPaths` แต่ละ Artifact มีพอร์ตพรีวิวและ origin ถาวรของตัวเอง `localStorage` ของพรีวิวจะถูกบันทึกลงในโปรเจกต์และซิงก์ เกมที่บันทึกไว้บนเครื่องหนึ่งจึงเล่นต่อบนอีกเครื่องได้ backend รันเป็นโปรเซสในเครื่องธรรมดา (ไม่ใช่ sandbox) พร้อม `PORT` และ `HOST` **Snapshot** จะหยุด backend และคัดลอก data path ที่ประกาศไว้ ส่วน **Restore** จะนำกลับคืน

ในพรีวิว *เลือกองค์ประกอบ ข้อความ หรือพื้นที่ของ canvas* แล้วเขียนความคิดเห็น: มันจะกลายเป็นงานสำหรับ agent ที่คุณเลือก โดยมีส่วนที่เลือกเป็นหลักฐาน (DOM path, ข้อความที่อ้างอิง หรือ PNG ของ canvas) ความคิดเห็นบน Artifact เดียวกันจะทำงานตามลำดับ ส่วน Artifact และบทสนทนาต่างกันจะทำงานแบบขนาน ดู `examples/persistent-game/` (backend Node + SQLite + Canvas) และ `examples/artifact-compatibility/`

## ไฟล์และการกำหนดค่า

| ตำแหน่ง | เนื้อหา |
| --- | --- |
| `projects/<id>/` | ไดเรกทอรีทำงานของโปรเจกต์: โค้ด, Artifact, ข้อมูล (ซิงก์) |
| `projects/<id>/.studio/events/` | บันทึกบทสนทนาที่เป็นแหล่งความจริงและเปลี่ยนแปลงไม่ได้ |
| `projects/<id>/.studio/state.json`, `history-index.md`, `sessions/`, `artifacts/` | สถานะที่สร้างใหม่ได้และประวัติที่อ่านได้สำหรับ agent |
| `projects/<id>/.studio/artifact-storage/`, `snapshots/`, `attachments/` | พื้นที่จัดเก็บพรีวิวที่ซิงก์, สแนปช็อตข้อมูล, หลักฐานของความคิดเห็น |
| `projects/<id>/uploads/` | ไฟล์ที่ลากวางลงในแชตหรือแผงทรัพยากร |
| `projects/.servers/` | แอดเดรสสาธารณะของเซิร์ฟเวอร์สำหรับการค้นพบ (ไม่มีความลับ) |
| `projects/.deleted/<id>.json` | ป้ายหลุมศพของโปรเจกต์ที่ถูกลบ (ซิงก์) โฟลเดอร์ที่ถูกสร้างขึ้นใหม่จากการซิงก์ที่มาช้าจะถูกลบอีกครั้ง |
| `~/.studio-local/` | ส่วนตัวของเครื่อง: ตัวตน, `accounts.json`, `accounts/<id>/`, การจับคู่, การตั้งค่า Tailscale — ห้ามซิงก์ |
| `~/.studio-local/agent-profiles.json` | ไม่บังคับ: path ของไฟล์ปฏิบัติการ / env ต่อตระกูล CLI (`claude`, `codex`) หรือต่อ id บัญชี |

การลบโปรเจกต์เป็นการลบถาวร (การเก็บถาวรยังย้อนกลับได้) และจะถูกปฏิเสธขณะที่มีงานอยู่ในคิว กำลังรัน หรือกำลังรอ เซิร์ฟเวอร์ที่ลบจะเขียนป้ายหลุมศพ จากนั้นลบโฟลเดอร์ `projects/<id>/` ทั้งหมด เครื่องมือซิงก์ของคุณจะนำทั้งสองอย่างไปยังเครื่องอื่น เมื่อเซิร์ฟเวอร์แต่ละเครื่องเห็นป้ายหลุมศพใหม่ จะลบสำเนาที่หลงเหลือของตัวเอง โปรเซส agent ที่ทำงานค้างอยู่และพอร์ตพรีวิว Artifact ของโปรเจกต์ รวมทั้ง transcript ของ Claude (`projects/<encoded path>*` ในแต่ละไดเรกทอรีการกำหนดค่า) และ rollout ของ Codex (จับคู่ด้วย `cwd` ในบรรทัดแรก) ที่มีไดเรกทอรีทำงานอยู่ภายในโปรเจกต์ ID ที่จัดการแล้วจะถูกบันทึกใน `~/.studio-local/purged-projects.json` โปรเจกต์ที่ถูก soft-delete โดยเวอร์ชันเก่า (`deletedAt`) จะถูกลบหนึ่งครั้งตอนเริ่มทำงาน

## คำถามที่พบบ่อย

**มันใช้ API key ของฉันไหม?** เฉพาะเมื่อคุณเพิ่มบัญชีแบบ API key บัญชีแบบสมัครสมาชิกทำงานผ่านการลงชื่อเข้าใช้ของ CLI เอง Studiolo ไม่เก็บข้อมูลรับรองใด ๆ ของตัวเอง

**`claude` / `codex` ในเทอร์มินัลของฉันจะได้รับผลกระทบไหม?** ไม่ บัญชีของ Studiolo อยู่ในไดเรกทอรีของตัวเอง `~/.claude` และ `~/.codex` ถูกอ่านเพียงครั้งเดียวเพื่อคัดลอกการตั้งค่าและลิงก์ skill

**นี่เป็น sandbox หรือเปล่า?** ไม่ใช่ agent และ backend ของ Artifact เป็นโปรเซสในเครื่องของคุณเองที่มีสิทธิ์ของคุณ เหมือนกับ CLI ในเทอร์มินัลทุกประการ

**ใช้จากโทรศัพท์ได้ไหม?** ได้ ในฐานะไคลเอนต์เบราว์เซอร์ผ่าน Tailscale ส่วน CLI รันบนคอมพิวเตอร์ของคุณ

**ทำไมไม่มี dependency เลย?** เซิร์ฟเวอร์เป็น Node.js ล้วน (ESM ใช้เฉพาะโมดูล `node:`) จึงรันได้ทุกที่ที่ Node 22 รันได้ และไม่มีสิ่งใดในซัพพลายเชนมาคั่นระหว่างคุณกับ CLI ของคุณ
