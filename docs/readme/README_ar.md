## التثبيت باستخدام وكيل برمجة

الصق هذا النص في Claude Code أو Codex أو أي وكيل برمجة قادر على تنفيذ الأوامر على الجهاز الذي تريد استخدامه:

```text
ثبّت Studiolo من https://github.com/a554b554/studiolo: انسخ المستودع (clone)، وتأكد من توفر Node.js 22.14 أو أحدث ومن تثبيت أداتَي `claude` و/أو `codex`، ثم شغّل `node src/server.mjs` من جذر المستودع، وتحقق من أن http://127.0.0.1:4310 يستجيب، ثم أخبرني أن أفتح Settings → Hosts & accounts لتسجيل الدخول إلى حساباتي. لا تسجّل الدخول إلى أي شيء بنفسك.
```

أو يدويًا:

```sh
git clone https://github.com/a554b554/studiolo studiolo && cd studiolo
node src/server.mjs        # http://127.0.0.1:4310
```

لا يعتمد Studiolo على أي حزم npm؛ لا حاجة إلى `npm install`. الاختبارات: `node --test test/*.test.mjs`.

## ما هو Studiolo

Studiolo منصة عمل ويب مستضافة ذاتيًا تُشغّل أداتَي **Claude Code** و**Codex** المثبتتين مسبقًا على حواسيبك. وهو ليس مجرد واجهة دردشة أخرى فوق مفتاح API:

- **اشتراكاتك، وأدواتك.** يمر كل طلب عبر عملية `claude` أو `codex` الحقيقية، بنفس الأدوات والمهارات وخوادم MCP وأوضاع الأذونات وسلوك الوكيل كما في الطرفية. تسجيل الدخول بالاشتراك أو بمفتاح API، والاختيار لك لكل حساب.
- **حسابات لكل جهاز يديرها Studiolo.** سجّل الدخول إلى عدة حسابات Claude وCodex على كل حاسوب من المتصفح. يحصل كل حساب على مجلد إعدادات CLI معزول خاص به؛ ولا يُمسّ `~/.claude` أو `~/.codex` الشخصي. وتظهر حصة كل حساب مباشرةً.
- **سجل مشاريع واحد عبر الأجهزة.** تعيش المشاريع في مجلد تزامنه بالطريقة التي تفضلها (Syncthing مثلًا). سجل المحادثات سجلٌ إلحاقي فقط يُدمج بطريقة حتمية؛ وكل جهاز يشغّل الخادم نفسه ويقدّم السجل نفسه. تُنفَّذ المحادثة على الجهاز الذي اخترته لها، ويمكنك قراءتها ومتابعتها من أي جهاز.
- **تجربة الطرفية داخل المتصفح.** أوقف دورة بالضغط على Esc، ووجّه وكيلًا قيد العمل برسالة متابعة، واكتب `/` لأوامر الشرطة المائلة الخاصة بـ CLI نفسها، وكل ذلك مربوط بالبروتوكولات الأصلية لا مُعاد تنفيذه.
- **Artifacts والتعليقات داخل الصفحة.** تعمل تطبيقات الويب التي يبنيها الوكلاء بوصفها Artifacts مع واجهات خلفية دائمة وتخزين متزامن؛ حدّد شيئًا في المعاينة وأرسله إلى وكيل بوصفه مهمة.

## البدء السريع

1. **المتطلبات المسبقة**: Node.js 22.14 أو أحدث، وأداة `claude` و/أو `codex` مثبتة على الجهاز (`claude --version`، `codex --version`).
2. **شغّل** `node src/server.mjs` وافتح <http://127.0.0.1:4310>.
3. **أضف الحسابات**: Settings → *Hosts & accounts* → *Add account*. اختر الجهاز والنوع (Claude Code / Codex) وطريقة تسجيل الدخول، ثم اتبع الخطوات المعروضة (انظر أدناه).
4. **أنشئ مشروعًا وابدأ محادثة**: يختار مربع الكتابة **الجهاز → الحساب → النموذج → مستوى الجهد → وضع الأذونات**. تُثبّت الرسالة الأولى الجهاز والحساب والنموذج لتلك المحادثة؛ أما مستوى الجهد والأذونات فيمكن تغييرهما مع كل رسالة.

متغيرات البيئة: `STUDIO_STATE_DIR` (حالة خاصة بالجهاز، الافتراضي `~/.studio-local`)، و`STUDIO_BIND`، و`STUDIO_PORT` (4310)، و`STUDIO_PREVIEW_PORT` (4311)، و`STUDIO_TOKEN`، و`STUDIO_UPLOAD_LIMIT` (بالبايت، الافتراضي 100 MB). خادم واحد لكل مجلد حالة.

## الحسابات وتسجيل الدخول

تنتمي الحسابات إلى جهاز وتُنشأ من المتصفح. كل حساب مجلد تحت `~/.studio-local/accounts/<id>/` يُستخدم بوصفه `CLAUDE_CONFIG_DIR` أو `CODEX_HOME`، فتتعايش عدة حسابات لأداة CLI واحدة ولا يُمسّ تسجيل الدخول الخاص بطرفيتك أبدًا. عند إنشاء حساب، يهيّئ Studiolo ذلك المجلد انطلاقًا من مجلد CLI الافتراضي لديك: ينسخ `settings.json` / `CLAUDE.md` (في Codex: `config.toml` / `AGENTS.md`) وينشئ روابط لـ `skills` و`plugins` وما شابهها، فيحتفظ الوكلاء بالمهارات وخوادم MCP التي تستخدمها أصلًا. لا تُنسخ بيانات الاعتماد أبدًا.

| النوع | الطريقة | ما يحدث |
| --- | --- | --- |
| Claude Code | **الاشتراك** | يشغّل Studiolo الأمر `claude auth login`؛ تفتح الرابط وتسجّل الدخول ثم تلصق رمز التفويض في الصفحة. |
| Claude Code | **مفتاح Anthropic API** | يُخزَّن المفتاح في مجلد الحساب (بالصلاحية 0600) ويُمرَّر بوصفه `ANTHROPIC_API_KEY`؛ يُتحقق منه عبر مصافحة CLI ويُحذف إن رُفض. الدفع حسب الاستخدام، بلا نوافذ حصص. |
| Codex | **ChatGPT** | رمز جهاز عبر app-server الخاص بـ Codex: تعرض الصفحة رابطًا ورمزًا لمرة واحدة؛ سجّل الدخول من أي متصفح، وتتحدث الصفحة عند الانتهاء. |
| Codex | **مفتاح OpenAI API** | يخزّنه Codex نفسه في `CODEX_HOME` الخاص بالحساب. |

بعد تسجيل الدخول يقرأ Studiolo هوية الحساب (البريد الإلكتروني، الخطة) وقائمة النماذج مباشرةً من CLI، دون استهلاك أي طلب نموذج، وبالنسبة إلى Claude يقرأ أيضًا أوامر الشرطة المائلة الخاصة بـ CLI للإكمال التلقائي في مربع الكتابة. يُعاد تسمية الحساب الذي لا يحمل اسمًا مخصصًا باسم بريده الإلكتروني، فيوضح مربع الكتابة وترويسة المحادثة وكل رد ولوحة الاستهلاك من المتحدث. يمكن إعادة تسمية الحسابات وتحديثها وتسجيل الخروج منها (`claude auth logout` / `codex logout`) أو إزالتها؛ ويمكن للمحادثة التي أُزيل حسابها أن تستمر بحساب آخر على الجهاز نفسه.

تتبع لوحة الاستهلاك (أسفل اليسار) الجهاز المختار في مربع الكتابة: تعرض اشتراكات Claude نافذة الساعات الخمس، وCodex النافذة الأسبوعية، أما حسابات مفاتيح API فتُحاسب حسب الاستخدام. تقرأ اللوحة نقاط نهاية الاستهلاك الخاصة بأدوات CLI نفسها (`get_usage`، `account/rateLimits/read`)، وتخزّن النتائج مؤقتًا لمدة 60 ثانية، ولا تستطلع دوريًا أبدًا، ولا تشغّل CLI لحساب مُسجَّل الخروج.

كل هذا يعمل مع الأجهزة البعيدة أيضًا: اختر مضيفًا آخر متصلًا في *Hosts & accounts* وتُمرَّر الطلبات إليه.

## الدردشة كما في CLI

تملك كل محادثة عملية أصلية مقيمة، Claude Code عبر `stream-json` ثنائي الاتجاه وCodex عبر `app-server`، فيتصرف الوكيل تمامًا كما في الطرفية. تُربط عناصر التحكم في الويب بالبروتوكولات الأصلية:

| في الطرفية | في Studiolo | الكيفية |
| --- | --- | --- |
| Esc للإيقاف | **■ Stop** أو Esc في مربع الكتابة | طلب التحكم `interrupt` في Claude / `turn/interrupt` في Codex. تبقى العملية والجلسة الأصلية قائمتين؛ ويُحتفظ بالرد الجزئي؛ وتتابع الرسائل اللاحقة الجلسة نفسها. |
| الكتابة أثناء عمل الوكيل | الإرسال أثناء تنفيذ دورة = **Steer** | يقرؤها Claude عند حد الأداة التالي؛ وفي Codex `turn/steer`. تظهر بوصف *You · steer*؛ ويتابع الرد في مقطع جديد. أما **Queue** فترسل الرسالة بعد انتهاء الدورة. |
| `/compact`، `/context`، الأوامر المخصصة، المهارات | اكتب `/` لعرض قائمة الأوامر | تمر أوامر Claude كما هي حرفيًا (القائمة تأتي من CLI نفسها). لا يملك Codex أوامر نصية؛ فتُربط `/compact` و`/review` و`/skills` و`/mcp` بطلبات app-server. |
| — | `/model`، `/effort`، `/mode`، `/rename`، `/new`، `/status`، `/clear`، `/stop`، `/help` | أوامر المنصة، تُعالج في المتصفح أو عبر الطابور. |

طلبات الأذونات التي كانت CLI ستطرحها في الطرفية تظهر في الصفحة: وافق لمرة واحدة أو ارفض، ويستمر التنفيذ نفسه. الوضع التلقائي هو وضع CLI نفسها (`auto` في Claude، و`auto_review` في Codex)؛ ولا يضيف Studiolo أبدًا أعلام تجاوز أو قواعد سماح دائمة. يمكن تغيير مستوى جهد الاستدلال والنموذج مع كل رسالة داخل المحادثة (`set_model` / `apply_flag_settings` في Claude، ومعاملات `turn/start` في Codex).

## تعدد الأجهزة

شغّل الخادم نفسه على كل حاسوب؛ وضع `projects/` في مجلد تزامنه (Syncthing أو أي أداة لمزامنة الملفات). المجلد `.studio/events/` لكل مشروع سجلٌ غير قابل للتعديل ومرتب سببيًا؛ كما تتبادل الأجهزة المتصلة السجلات مباشرةً فتظهر التغييرات خلال ثوانٍ. يستطيع أي جهاز عرض كل المحادثات؛ لكن التنفيذ يحدث دائمًا على الجهاز المرتبطة به المحادثة، ولا تنتقل جلسات CLI الأصلية بين الأجهزة أبدًا.

**الوصول إلى الأجهزة الأخرى.** أبسط إعداد آمن هو [Tailscale](https://tailscale.com): ضع `tailnet.json` (`{"enabled":true,"command":"tailscale"}`) وملف `access-token.txt` عشوائيًا (32 حرفًا على الأقل) في مجلد الحالة، وشغّل الخادم كالمعتاد، فينشر Studiolo منفذه عبر `tailscale serve`؛ افتح `http://<machine>:4310` وأدخل الرمز مرة واحدة. مع `"trustTailnet":true` يُتجاوز الرمز لحركة المرور القادمة من tailnet. ومن دون Tailscale، اربط الخادم بعنوان خاص عبر `STUDIO_BIND` واضبط `STUDIO_TOKEN`. تكتشف الخوادم بعضها عبر `projects/.servers/` أو عبر الإقران اليدوي في Settings.

**التشغيل التلقائي.** على macOS: يثبّت `node scripts/install-studio-macos.mjs` وكيل LaunchAgent (`net.studio-local.server`). على Windows: سجّل `scripts/start-studio-windows.ps1` بوصفه مهمة في Task Scheduler (الإجراء `conhost.exe --headless powershell.exe -NoProfile -NonInteractive -ExecutionPolicy Bypass -File <path>`، التشغيل عند تسجيل الدخول، بلا نسخ مكررة، وإعادة المحاولة كل دقيقة)؛ ويعيد `scripts/restart-studio-windows.ps1` تشغيله بعد الترقية حالما لا توجد عمليات تشغيل نشطة.

**الترقية.** تُقرأ ملفات الواجهة الأمامية تحت `public/` مع كل طلب وتسري فور مزامنتها؛ أما التغييرات تحت `src/` فتحتاج إلى إعادة تشغيل على كل جهاز.

## Artifacts والتعليقات داخل الصفحة

اطلب من وكيل صفحة ويب أو تطبيقًا وسيتولى صيانة `studio.artifacts.json` في جذر المشروع:

```json
{
  "artifacts": [
    { "key": "game", "name": "Click the target", "root": "game", "entry": "index.html",
      "command": ["node", "server.mjs"], "port": 4320, "dataPaths": ["game/data"] }
  ]
}
```

تحذف الصفحات الثابتة `command` و`port` و`dataPaths`. يحصل كل Artifact على منفذ معاينة ومصدر (origin) دائمَين خاصَّين به؛ ويُحفظ `localStorage` الخاص بالمعاينة داخل المشروع ويُزامن، فاللعبة المحفوظة على جهاز تستمر على جهاز آخر. تعمل الواجهات الخلفية بوصفها عمليات محلية عادية (لا بيئة معزولة) مع `PORT` و`HOST`؛ يوقف **Snapshot** الواجهة الخلفية وينسخ مسارات البيانات المُعلنة، ويعيدها **Restore**.

في المعاينة، *حدّد عنصرًا أو نصًا أو منطقة من لوحة الرسم (canvas)* واكتب تعليقًا: يصبح مهمة للوكيل الذي تختاره، مع التحديد بوصفه دليلًا (مسار DOM، أو النص المقتبس، أو صورة PNG من لوحة الرسم). تُنفَّذ التعليقات على Artifact واحد بالترتيب؛ أما الـ Artifacts والمحادثات المختلفة فتُنفَّذ بالتوازي. راجع `examples/persistent-game/` (واجهة خلفية Node + SQLite + Canvas) و`examples/artifact-compatibility/`.

## الملفات والإعدادات

| الموقع | المحتوى |
| --- | --- |
| `projects/<id>/` | مجلد عمل المشروع: الشيفرة وArtifacts والبيانات (متزامن) |
| `projects/<id>/.studio/events/` | سجل المحادثات المرجعي غير القابل للتعديل |
| `projects/<id>/.studio/state.json`، `history-index.md`، `sessions/`، `artifacts/` | حالة قابلة لإعادة البناء وسجل مقروء للوكلاء |
| `projects/<id>/.studio/artifact-storage/`، `snapshots/`، `attachments/` | تخزين المعاينة المتزامن، ولقطات البيانات، وأدلة التعليقات |
| `projects/<id>/uploads/` | الملفات التي تُسقط في الدردشة أو في لوحة الموارد |
| `projects/.servers/` | العناوين العامة للخوادم لأغراض الاكتشاف (بلا أسرار) |
| `projects/.deleted/<id>.json` | شواهد المشاريع المحذوفة (متزامنة)؛ ويُزال مجددًا أي مجلد تعيد مزامنة متأخرة إنشاءه |
| `~/.studio-local/` | خاص بالجهاز: الهوية، `accounts.json`، `accounts/<id>/`، الإقران، إعدادات Tailscale؛ لا تزامنه أبدًا |
| `~/.studio-local/agent-profiles.json` | اختياري: مسار الملف التنفيذي / متغيرات البيئة لكل عائلة CLI (`claude`، `codex`) أو لكل معرّف حساب |

حذف المشروع نهائي (أما الأرشفة فقابلة للتراجع)، ويُرفض ما دام هناك عمل في الطابور أو قيد التشغيل أو في الانتظار. يكتب الخادم الذي ينفّذ الحذف شاهدًا، ثم يزيل المجلد `projects/<id>/` بالكامل؛ وتنقل أداة المزامنة كليهما إلى الأجهزة الأخرى. عندما يرى كل خادم شاهدًا جديدًا، يزيل نسخته المتبقية، وعمليات الوكلاء المقيمة الخاصة بالمشروع ومنافذ معاينة Artifacts، ونصوص محادثات Claude (`projects/<encoded path>*` في كل مجلد إعدادات) وسجلات Codex (rollouts) (المطابَقة عبر `cwd` في سطرها الأول) التي كان مجلد عملها داخل المشروع. تُسجَّل المعرّفات المعالَجة في `~/.studio-local/purged-projects.json`. أما المشاريع المحذوفة حذفًا مرنًا في الإصدارات الأقدم (`deletedAt`) فتُزال مرة واحدة عند بدء التشغيل.

## الأسئلة الشائعة

**هل يستخدم مفتاح API الخاص بي؟** فقط إذا أضفت حسابًا بمفتاح API. تعمل حسابات الاشتراك عبر تسجيل الدخول الخاص بأدوات CLI نفسها؛ ولا يخزّن Studiolo أي بيانات اعتماد خاصة به.

**هل سيتأثر `claude` / `codex` في طرفيتي؟** لا. تعيش حسابات Studiolo في مجلداتها الخاصة؛ ولا يُقرأ `~/.claude` و`~/.codex` إلا مرة واحدة لنسخ الإعدادات وربط المهارات.

**هل هذه بيئة معزولة (sandbox)؟** لا. الوكلاء والواجهات الخلفية لـ Artifacts عمليات محلية خاصة بك تعمل بأذوناتك، تمامًا مثل أدوات CLI في الطرفية.

**هل يمكنني استخدامه من هاتفي؟** نعم، بوصفه عميل متصفح عبر Tailscale؛ أما أدوات CLI فتعمل على حواسيبك.

**لماذا بلا أي اعتماديات؟** الخادم مكتوب بـ Node.js خالص (ESM، ووحدات `node:` فقط)، فيعمل في أي مكان يعمل فيه Node 22، ولا يقف أي شيء من سلسلة التوريد بينك وبين أدوات CLI الخاصة بك.
